# session-timeline

`timeline.ts`が並べて数え、モデルが読んで判断する。

```bash
bun ${CLAUDE_SKILL_DIR}/timeline.ts <セッションID> > ~/.claude/tmp/<名前>-timeline.txt
```

出力は長いので、ファイルに書いてから読む。セッションIDは、claude-deckのセッションなら`claude-deck list`の`claude_session_id`で引く。

## 出力の読み方

- **時系列**: 届いた文（利用者、別のセッションからの依頼、サブエージェントの報告、Modの知らせ、完了の知らせ）がターンの始まり。その下に、スキルとサブエージェントの呼び出しと、その間の作業（ツールの回数）が並ぶ。「裏」のサブエージェントの時間は、本体の時間と重なる
- **Agentの呼び出しに結び付かないサブエージェント**: `context: fork`のスキル（`/review-code`など）と、Modが立てたもの（retroの書き手）
- **まとめ**: 本体が動いていた時間、サブエージェントの種類ごとの回数と時間、スキルの回数、本体のツールとBashのコマンドごとの時間

## 判断するときの見どころ

工程の決まりは`~/.claude/CLAUDE.md`の「サブエージェント」の節にある。それと突き合わせる。

- 同じ差分に、同じ種類のレビューを2回走らせていないか（`review-code`のスキルと、`code-review`のエージェントか、レビューを頼んだ`general-purpose`の両方など）
- 振る舞いを変える区切りで、`test-designer`、`verifier`、`review-code`のどれかが抜けていないか。文言だけの直しで立てていないか
- 本体のBashで長いもの。同じ確かめを何度も手で打っているなら、スクリプトにする候補になる

## Gotchas

- 1回の応答は内容のブロックごとに別の行に記録され、同じ`usage`が重なって入っている。スクリプトは`message.id`で1回だけ数えている。手で集計するときも同じにする
- 金額は出さない。記録に金額は無く、モデルごとの単価を掛ける必要がある
