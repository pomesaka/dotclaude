# correct

retroは、会話から学びを集めてdotclaudeの文書とスキルを育てる。このスキルは、作業しているプロジェクトのリポジトリを直して、同じ間違いをできなくする。段の順は`~/.claude/docs/shared-agent-policy.md`の「判断の原則」と同じで、このスキルはそれを、くり返された間違いに当てはめる手順だ。

エージェントは、開いたファイルしか見ず、いちばん近い例を写し、型検査が通るいちばん短い道を選ぶ、と考えて直す。1つのファイルから見て正しそうな変更が、リポジトリ全体でも正しくなる形にする。

## 1. 間違いを集めて種類に分ける

引数があれば、その間違いから始める。無ければ、次から探す。

- 最近のコミットとrevert（`jj log`、`jj diff`）
- PRのレビューのコメント（`gh pr list --state merged`、`gh api repos/{owner}/{repo}/pulls/{n}/comments`）
- リポジトリの`CLAUDE.md`、`AGENTS.md`、`docs/`の規則と、回り道を説明しているコメント
- retroの控えの仕組みの候補（`/retro candidates`で、pomesakaに出してもらう）

間違いを、起こした判断ごとに種類にまとめる。見た目が違っても、同じ判断から起きていれば同じ種類だ。2回起きたものを種類として数える。

## 2. 種類ごとに、いちばん上の段で直す

上から順に試し、効く段で直す。下の段を選んだら、上の段が効かなかった理由を言えるようにする。

1. **構造でなくす。** 状態の持ち主を1つに、作業のやり方を1つにする。中身を隠し、間違った import が失敗するようにする。手で揃えている一覧を、1つの情報源から導く。エージェントが写しそうな古いやり方と使われていないコードを消す
2. **型で、間違った状態を書けなくする。** 型で止められず通ってしまうなら、lintかCIの検査を足す。エラーの文に、代わりに使うファイル、型、関数の名前を出す。もう多く使われている書き方なら、増えたときだけ落とす
3. **振る舞いをテストする。** 守る振る舞いが壊れても通るテストと、中身を変えただけで落ちるテストは、直すか消す（`~/.claude/docs/testing-policy.md`）
4. **文書か、エージェントの規則に書く。** 判断が要るものだけにする。読まれなくても何も落ちないので、最後の手段だ

## 3. 直して、落ちることを確かめる

多く起きている種類から直す。

- 新しい検査は、過去に実際に起きた間違いを1つもう一度入れて、落ちることを確かめる。落ちたコマンドと出力を報告に貼る。確かめたら、入れた間違いは戻す
- 手元とCIで同じコマンドを走らせる。手元だけの検査は、ほかの人とエージェントを止めない
- 例外は、その行に理由、期限、承認した人を書く
- コミットは、pomesakaに頼まれたときに、種類ごとに1つずつ分けて行う

## 4. 規則と、それを強制するものの表を保つ

リポジトリのエージェント向けの文書（`CLAUDE.md`か`AGENTS.md`）に、規則と、それを強制するもの（型、lintのルールの名前、テスト、無ければ「なし」）の表を置く。無ければ作る。

- 訂正を受けたら、直したうえで、表に規則を足す
- 表に規則があったのにまた起きたら、強制が無いのでくり返したのだから、同じ変更の中で上の段へ上げる
- 間違いが起きなくなった規則（構造でなくした、型で書けなくした）は、表から消す

## 報告

種類ごとに、根拠（コミット、コメント、file:line）、選んだ段、上の段を選ばなかった理由、落ちることを確かめたコマンドを書く。直していない種類があれば、その理由も書く。
