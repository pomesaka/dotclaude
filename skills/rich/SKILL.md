# rich

`mcp__rich__show`ツールで、短い説明をターミナルに描く。ツールは`mods/rich`のModが登録する。ツールが一覧に無いセッション（Modを読み込んでいない、ターミナル以外で開いている）では使えないので、文章で答える。

## 使うかどうか

ふだんの報告は文章と表のまま書く。文章は選んでコピーでき、どの画面からも読めるからだ。`show`を使うのは、次のどれかを含むときだけにする。

- **案を2つか3つ比べる:** カードを横に並べる
- **流れや関係を説明する:** 箱と矢印の図にする
- **番の終わりに、次の一手を選んでもらう:** 質問のボタンにする

報告の全文を`show`に入れない。本文は文章で書き、図や選択肢の部分だけを`show`で出す。

## どこに出すか

決め手は「読んだあと、その説明がまだ要るか」。

| 出し方 | 使う場面 |
|---|---|
| `where: "inline"` | 1画面に収まり、読んでその場で答えて終わるもの。迷ったらこれ |
| `where: "pane"` | 横に出したまま会話や作業を続けたいもの。作業の計画、議論している構成の図など |
| `explain`スキル（HTML） | 2画面を超える長さ、斜めの線や多くの箱が要る図、あとで見返したいもの |

## 質問とAskUserQuestionの使い分け

基準は「答えが無いと、この番の作業を続けられないか」。

- **続けられない:** `AskUserQuestion`を使う。答えが来るまで番が止まり、同じ番の続きで作業に戻れる
- **番はもう終わっている:** `show`の質問を使う。番を止めず、答えは利用者の次の発言として届く

`show`の質問を作業の途中で使うと、答えが来る前に番が終わって作業が中断する。逆に、作業が終わった後の「次はどれにしますか」に`AskUserQuestion`を使うと、利用者が答えるまで番が閉じない。

質問付きで`show`を呼んだら、同じ問いを文章で繰り返さずに番を終える。答えは次の形で届く。

```
【<title> への回答】
1. <question>: <選んだoption>
```

## 入力

```json
{
  "title": "保存の方式",
  "blocks": [
    { "type": "text", "text": "書き込みが失敗したときの扱いが違います。" },
    { "type": "cards", "key": "plan", "question": "方式", "cards": [
      { "title": "案A 同期", "lines": ["保存が終わるまで待つ", { "text": "失敗がその場で分かる", "tone": "good" }, { "text": "遅い", "tone": "warn" }] },
      { "title": "案B 非同期（いまの実装）", "value": "案B 非同期", "lines": ["キューに積んで返す", { "text": "速い", "tone": "good" }, { "text": "失敗を後で知る", "tone": "warn" }] }
    ] },
    { "type": "diagram",
      "nodes": [{ "id": "api", "title": "API", "note": "受け付ける" }, { "id": "q", "title": "Queue" }, { "id": "db", "title": "DB", "note": "保存する" }],
      "edges": [{ "from": "api", "to": "q", "label": "積む" }, { "from": "q", "to": "db" }] }
  ]
}
```

- **`text`:** Markdown。段落、箇条書き、コード。表はなるべく書かない（下の「表を避ける」）
- **`cards`:** 2〜3枚。`lines`の各行は文字列か`{ text, tone }`。`tone`は`plain` `good` `warn` `dim`
- **カードで選ばせる:** `cards`のブロックに`key`と`question`を付けると、カードが選択肢になり、題名を押して選べる。答えとして送られるのは各カードの`value`で、無ければ題名。題名に「（いまの実装）」のような添え書きを付けるときや、答えの綴りが決まっているときは、`value`を別に書く
- **`diagram`:** 箱（`nodes`）と矢印（`edges`）。位置はModが決めるので指定しない
- **`question`:** カードで見せない選択肢を聞くときに使う。`key`は説明の中で重複させない。`question`は答えの文に入る短い名前にする。`options`は2つ以上。**カードで比べた案を選ばせるときは、同じ選択肢を`question`で並べ直さず、カードを選択肢にする**
- **`tabs`:** `{ "type": "tabs", "tabs": [{ "label": "案A", "blocks": [...] }, ...] }`。見出しを押すと下の中身が入れ替わる。タブは2つ以上。中に置けるのは`text` `cards` `diagram`だけで、`question`と`tabs`は置けない

## 表を避ける

paneの幅はターミナルの半分ほどしかない。表はpaneの幅に合わせて描かれないので、罫線とセルが折り返して読めなくなる（2026-10-10に実機で確認。3列で、1列に長い文がある表）。

| 出す先 | 書き方 |
|---|---|
| pane | 表を書かない。1行を箇条書きの1項目にして、先頭に名前を太字で置き、残りを続ける。2〜3件の見比べならカードにする |
| 会話の中 | どのセルも数語で言える表だけにする。文が入るセルがあれば箇条書きにする |

```
- **iori-a95c**（実装中）: PR 2bの前半。2つめの配信元を受け入れる
- **anna-4aa4**（作業中）: 照合のドライバの下準備
```

## カードとタブの使い分け

会話の中は高さが限られる。案ごとに図や説明があって縦に並べると1画面を超えるなら、タブにして1案ずつ見せる。

| 部品 | 使う場面 |
|---|---|
| `cards` | 各案が数行で言えて、横に並べて一目で見比べたい |
| `tabs` | 各案に図や長い説明があり、並べると長くなる。1案ずつ詳しく見せたい |

両方を使ってもよい。先にカードで全体を見せ、その下にタブで各案の詳細を置く。質問はタブの外に置く。

文は`~/.claude/docs/japanese-writing.md`の規則で書く。カードの行と図のラベルは短く切る。

## 図の限界

箱は矢印の向きに沿って左から右へ並ぶ。描けるのは横と縦の線と直角の曲がりだけになる。

- 箱の列は4つくらいまで、ラベルは短くする。幅が足りないと右側が切れ、図の下にその旨が出る
- 会話の中の幅はターミナルの幅、paneの幅はその半分ほどになる。paneに出す図は列を3つまでにする
- これを超える図は`explain`で描く

## Gotchas

- **会話の流れに合わない回答が届いたら、そのまま従わずに確かめる:** 過去の行のボタンは、古い質問でも押せることがある。すでに片付いた件への回答、いまの話題と関係の無い回答が届いたら、押し間違いや動作確認の可能性がある。消したものを戻す、といった操作をする前に、利用者に確かめる（2026-10-09。答え済みの「古いステータス行を消すか」に、開き直した後で「残す」が届いた）
  <!-- importance: high | mentions: 1 | first-seen: 2026-10 -->
- **答えた質問には答え直せない:** 送ると質問は閉じる。開き直しても閉じたままで、選んだ答えが読める。答えを変えたいときは、利用者に文章で言ってもらう
- **開いているタブは覚えていない:** セッションを開き直すと、最初のタブに戻る。いちばん見てほしい案を1つ目に置く
- **入力が合わないとツールが失敗し、どこが悪いかが返る:** `blocks[0].edges[1] names "x", which is no node id`のような文になる。直して呼び直す
- **paneは、ターミナルが狭いと開かないことがある:** ツールの結果に`The pane is not drawn yet`と出たら、利用者に`/rich-pane`を打ってもらう（`/rich`はこのスキルの名前なので、Modのコマンドは別の名前にしてある）。利用者が開いたpaneは幅に関係なく出る

- **絵（PNG）は出せない:** Claude Codeはtmuxの中で絵を描かない（v2.1.295で確認）。図は箱と矢印で表せる範囲にする
