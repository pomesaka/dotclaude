# update-pr の整理で移した項目（2026-11-28）

push と `gh pr edit` を `pr-push.sh` に任せた後、スクリプトが防ぐようになった手で打つときの注意。

## 1. push と本文の更新は pr-push.sh に任せる

残した原則: 手順 5 の「push と本文の更新は create-pr の `pr-push.sh` に任せ、`jj git push` と `gh pr edit` を手で打たない」と、Gotchas の「本文は書き直した後に読み直す」。

> - **`gh pr edit`の前に、`jj bookmark list`でbookmarkがoriginより先に進んでいない（`ahead by N commits`が出ない）ことを見る**: 手順5のpushを飛ばして本文だけを更新したことがある。PRのURLは返るので、コードがpushされていないことに利用者が気づくまで分からない。
> - **本文の書き換えと`gh pr edit`を、1つのコマンドに`;`でつながない**: 本文を直すスクリプトが途中で落ちても、`;`で続けた`gh pr edit`は走り、古い本文が公開される。本文はEditで直し、`gh pr edit`は別の呼び出しにする。更新の後は、`gh pr view <N> --json body --jq .body`を`rg`にかけて、本文が空でないことと、古い記述（日付、件数）が残っていないことを見る。
> 本文はファイル（`~/.claude/tmp/pr-body-<PR番号>.md`）に書き、`--body-file`で渡す。`--body "$(cat <ファイル>)"`は、ファイルが無いと空の本文で上書きして成功する。`--body-file`なら、ファイルが無いときにghがエラーにするので、本文が消えない。
> WHY: `jj desc → jj git push → gh pr edit` を毎回手で打っていた（find-repeats で 15 セッションに出た、2026-11-18）。
