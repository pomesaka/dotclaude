# dotclaudeの変更をまとめてコミットする

dotclaudeの作業コピーは、`~/.claude`のリンクを通して、いくつものプロジェクトのセッションが直接書いている。書いたセッションは自分ではコミットしない。このスキルは、dotclaudeで開いたセッションが、溜まった変更を関心事ごとにコミットし、pushするまでを行う。コミットとpushは、利用者に頼まれたときだけ行う。

判断の要らない手は`sync.ts`が受け持つ。このスキルの本文は、判断の所だけを書く。

## 1. 分け方を決める

```bash
bun ~/.claude/skills/dotclaude-sync/sync.ts plan
jj diff --git
```

`plan`は、dotclaude-ledgerのModの記録から、変わっているファイルを書いたセッションごとに束ね、依頼の文（`why`）を添えて出す。複数のセッションが書いたファイルと、記録の無いファイル（利用者が手で編集したか、Bashで書いたか、Modを入れる前の変更）は別に出る。

差分を全部読んでから、1つの理由で入った変更を1つのコミットにまとめる。

- 1つのファイルに別々の理由の変更が混ざっていたら、ファイルごと近いコミットに入れ、混ざった変更をメッセージに1行ずつ書く。行の単位で分けるには`jj split`の対話の画面が要り、そこまでの厳密さは求められていない（pomesakaの判断、2026-11-18）
- 書きかけに見える変更は、コミットせずに作業コピーに残し、利用者に伝える
- 記録の`why`が「振り返って」のような依頼の文なら、差分から、何を学びとして足したかを読み取る

## 2. 中身を確かめる

```bash
bun ~/.claude/skills/dotclaude-sync/sync.ts check
```

`check`は、作業コピーで足した行を`check-public.sh`と同じ規則で調べ、`~/.claude/…`のパスが実在するかを見る。スキルと`scripts/`のTypeScriptの型検査とテスト、変えたModの`claude plugin validate`と`claude plugin test`も走らせる。

スクリプトでは止められないものは、足した行を読んで確かめる。

- **名前:** 一覧に無い人名、社名、案件名、顧客のサービス名。見つけたら「ある案件で」のように一般化して直す。直しても、記録を書いたセッションの意図（`why`）を変えない
- **手順とコマンド:** 文書に書かれたコマンドは、手元で実行できるなら実行して確かめる。確かめられないものは、報告で「未確認」と書く
- **出典:** 外部の記事を出典に挙げた行は、その記事を読んで、書かれた内容と合っているかを確かめる
- **画面のデザインの学び:** 画面の組み立て、ラベルと補足の文、部品の使いどころ、状態の見せ方の学びは、dotclaudeにはそのままコミットし、ui-design（`~/github.com/pomesaka/ui-design`）のリポジトリで開いているセッションにも`SendMessage`で伝える。セッションは`claude-deck list`の`work_dir`で探し、無ければ報告に挙げる。振り返りはdotclaudeに全部集め、画面の学びだけをui-designへ渡す形にしている（pomesakaの判断、2026-11-19）。ui-designは公開のリポジトリで、受けた側がプロダクトに依らない書き方に直して入れる

## 3. コミットする

メッセージを一時ファイルに書き、`commit`に渡す。

```bash
bun ~/.claude/skills/dotclaude-sync/sync.ts commit -F <メッセージのファイル> <パス…>
```

形はこのリポジトリの履歴に合わせ、`docs(<対象>): <何をしたか>`のように書く。本文にはWHYを書く。末尾には、システムが渡した帰属の行（`Co-Authored-By`と`Claude-Session`）を入れる。

記録の`cwd`、セッションのID、`why`の文は書き写さない。プロジェクトのパスや依頼の文には、案件名や顧客の名前が入っている。WHYは「ある案件で、〜を取り違えた」のように一般化して書く。`commit`は、帰属の行が無いメッセージと、記録にあるプロジェクトの名前やセッションのIDが入ったメッセージを止める。

## 4. pushする

```bash
bun ~/.claude/skills/dotclaude-sync/sync.ts push
```

`push`は、`jj git fetch`をしてリモートの`main`が進んでいれば、その上へrebaseする。そのあと`main`を動かし、`check-public.sh`を通してからpushし、作業コピーに残っていないファイルの記録を消す。rebaseで競合したとき、`check-public.sh`が何かを挙げたときは、pushせずに止まる。挙がった行を直してからやり直す。誤検知だと考えたら、直さずに利用者へ伝える。

## 報告

コミットごとに、ID、題、どのセッションの変更か（「別のプロジェクトのセッションのretro」のように、名前を出さずに）を1行で書く。作業コピーに残したもの、確かめられなかったことがあれば、その理由も書く。
