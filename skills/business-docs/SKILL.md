# business-docs

## 目的

システムが無くても成り立つ業務を先に書き、システムの範囲と画面はそれにひも付ける。画面の手順だけの文書は実装の写しになり、システムが間違っていても気づけないからだ。

## 用意するもの

| 文書 | 中身 | 目的 |
|---|---|---|
| 業務フロー | 登場者（人と外部のサービス）、業務の一覧（起点・終わり・システム化の度合い）、業務ごとのスイムレーン図 | 誰が何をすると何が起きるかと、どこまでをシステムが受け持つかを 1 か所で見せる |
| 状態モデル | 業務で状態が変わる「もの」ごとの、状態と出来事の表 | 業務フロー同士をつなぎ、同じ状態変化を何か所にも書かずに済ませる |
| 業務の決まり | お金・受け付け・関係者とのやりとりの決まりと、その理由 | 決まりを 1 か所に集め、理由ごと残す |
| 利用者ごとのマニュアル | 利用者（運営、顧客など）ごとに、どの画面で何を操作するか | 画面の操作を業務の文書から外す。顧客向けも手順書の形で書き、清書（PDF など）は営業に任せる |
| 仕様 | スコープ、技術の判断、システムの裏の動き、未実装、対象外、要確認 | 業務の文書にもマニュアルにも入らない、システムの振る舞いと技術の判断を残す |
