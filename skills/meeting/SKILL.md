# meeting

会議 1 回ぶんを、始める → 聞く → 止める → 議事録を書く、の順に進める。音を聞いて文字起こしを読む部分は listen スキルの手順に従い、このスキルはその前後と、議事録の中身を受け持つ。

議事録のリポジトリに固有のこと（定例の一覧、置き場の名前、知らせの出し方）は、そのリポジトリの `CLAUDE.md` にある。どの会議か（置き場）は、引数か「【会議の時刻】」の文から決める。

## 1. 始める

1. `AskUserQuestion` で、始めるかと入り口を聞く。選択肢は `web`（Meet や Slack のハドル）、`mic`（対面）、`今日はやらない`。知らせは開始の 2 分前に出るので、利用者は会議に入る直前に押す
2. 別の会議の xlisten がまだ動いていたら、止めてよいかを先に聞く。止めたら、その会議の議事録を書いてから次へ進む
3. `/listen <web|mic>` の手順で聞き始める
4. 聞き始めたら次を読む。会議中に話者や聞き違いを当てるのに使う
   - 置き場の `CLAUDE.md`。親のディレクトリにもあれば両方（例: `<相手>/CLAUDE.md` と `<相手>/<会議>/CLAUDE.md`）。参加者、役割、聞き違えやすい語が書いてある
   - 同じ置き場の前回の議事録の「宿題」と「未決」
   - 直前の会議を受ける会議なら、その日の直前の会議の議事録（例: 取引先との定例の直後に開く内部のキャッチアップなら、その日の取引先との定例の議事録）
5. 置き場のディレクトリが無ければ作る。定例でない会議は相手ごとのディレクトリに置く
6. ホワイトボードを用意して、ブラウザで開く（下の「ホワイトボード」）

## ホワイトボード

会議中、話の中身をローカルのホワイトボード（xwb）に書き足していく。発言を時系列で並べるのではなく、論点、決まったこと、宿題、未決を付箋に、仕組みや比較を図にする。Artifact には出さない（利用者の指示。社外の会議の中身を claude.ai に置かないため）。

**xwb の使い方は `/xwb` スキルに従う**（何で描くか、付箋の色、進め方、SVG、コメントへの返事、守ること）。ここには会議に固有のことだけを書く。

- **ボードは会議の種類ごとに 1 枚を使い続ける**: `<置き場>/<置き場の最後の名前>.board.json`（例: `<相手>/<会議>/<会議>.board.json`）。無ければ `xwb open <ボード> --title "<会議の名前>"` で作る。WHY: 定例は宿題と未決が次の回へ持ち越されるので、毎回まっさらだと前回の分を描き直すところから始まる（利用者の判断、2026-11-17）。定例でない会議は、相手ごとに 1 枚
- まとめの帯は 3 列「今回決まったこと / 宿題 / 未決」。宿題と未決は開いているものを持ち越し、片付いたら消す。「今回決まったこと」は回の始めに空けて、その回の分だけを書く（前の回の決定は、議事録とその回の PNG に残っている）
- 議題のセクションは日付でなく話題ごとに置き、同じ話題は前の回のセクションに書き足す。片付いた話題のセクションは、回の終わりに消す
- ほかは `/xwb` スキルの「ボードの組み立て」に従う
- 文字起こしの聞き違いは、置き場の `CLAUDE.md` の語で直して書く
- **書き足しはサブエージェントに任せる**: 議題が変わったとき、何かが決まったとき、または前回から 5 分たったときに、Agent（`model: "sonnet"`、`run_in_background: true`）を立てる。渡すのは、`/xwb` スキルのパス（`~/.claude/skills/xwb/SKILL.md`）と xwb の `agent-guide.md` のパス、置き場の `CLAUDE.md` のパス、ボードのパス、文字起こしの `events/` のパス、前回どこまで読んだか（`at`）。サブエージェントは `xwb ls` で今のボードを読み、`at` より後の行を読んで書き足し、`xwb check` を通してから、最後に読んだ `at` を返す。WHY: 毎回メインで書くと、会議 1 時間ぶんの書き換えでメインの文脈が埋まる
  - 頼む文には「1 つのセクションの付箋が 5 枚を超えたら、新しく足さずに既存の付箋を `set` で書き換えるか 1 枚にまとめる」と、条件を数で入れる。WHY: 書き足しを頼むたびに付箋が増え、「増やしすぎない」という言葉だけでは 1 つのセクションに 10 枚を超えてたまった。会議の終わりに半分以上をまとめ直すことになる
- 利用者がボードについて頼んだこと（「この話を図にして」、コメント）は、メインで直してよい
- **画面で共有している資料は、文字起こしより確かな情報源として扱う**: 聞き始めたら、画面で共有している資料（議題の表など）があるかを利用者に聞き、あればスクショをもらう。参加者は資料を見て話しているので、文字起こしで崩れた語や数値は資料で正しく直せる。語や数値が文字起こしと資料で食い違ったら資料を正とし、それまでのボードと議事録の事実も資料に合わせて直す。スクショは置き場に `YYYYMMDD-<内容>.png` で保存し、表やガントにしてボードに足す

## 2. 聞いている間

listen スキルの「聞いている間」に従う。会議の記録で足すことは次のとおり。

- **話者の対応を教えてもらったら、記録を 2 か所に書く**: `<出力フォルダ>/inbox.txt` に 1 行足し、新しい人や役割は置き場の `CLAUDE.md` に足す。記号（A・B…）は起動のたびに振り直されるので、置き場の `CLAUDE.md` には記号ではなく、役割と話し方（進行役、質問を持ち込む人）を書く。次回はそれで記号を推せる
- **聞き違えやすい語が分かったら、置き場の `CLAUDE.md` に足す**: 社名、製品名、システム名。次回の議事録で最初から正しく書ける
- **利用者の「？」には議論で答える**: 会議の内容への質問（「何が問題になってる？」「〜どう思う？」）には、文字起こしから流れをまとめて答え、意見を言う。意見の前提が推測なら推測と書く
- **会議の発言に事実の誤りがあれば、そっと補足する**: 利用者にだけ見える形で、1〜3 行で書く。会議を止めさせるためではなく、利用者が後で確かめるため

## 3. 止める

利用者が「終わり」「おわり〜」などと言ったら止める。議事録が要るかは聞かない（毎回書く）。

1. listen スキルの「止める」の手順で xlisten を止める
2. Monitor は `sleep 60` ごとにまとめて渡すので、止めた時点で最後の 1 分ぶんが届いていない。最後の知らせが届いてから TaskStop するか、`events/` の残りを読んでから議事録を書く
3. 次の会議がすぐ続くなら（リポジトリの `CLAUDE.md` の定例の一覧に書いてある）、議事録を書く前に、次の会議を始めるかを聞く。時刻の知らせを待たない。二重にならないよう、その会議の時刻の知らせは `CronDelete` で消す
4. ボードの最後の書き足しを済ませ、`xwb compact <ボード> --fit` で空いた段を詰めてから、`xwb shot <ボード> --scale 1` で `<置き場>/YYYYMMDD.board.png` に保存する。PNG は、その回の終わりの形を残すためのもの（ボードは次の回で書き換わる）

## 4. 議事録を書く

形は [template.md](template.md) に従う。ボードと文字起こしの両方から書く。ボードで決まったことや宿題として書いたものは、議事録でも同じ言葉にする。

- 書く前に `xwb changes <ボード>` で、利用者がボードに書き足したり直したりした付箋を読み、議事録に入れる。入れ終わったら `--clear`
- ファイルは `<置き場>/YYYYMMDD.md`。同じ日に同じ会議が 2 回あれば `YYYYMMDD-2.md`
- 終わった時刻は `date` で取る
- 書いたら、ファイルのパスと、決まったことの要点を 1〜3 行で利用者に伝える

**推して書いたところは、保留に残す**: 話者、聞き違えた名前、担当。`mcp__questions__add_question` の `detail` には、根拠の文字起こしの行をそのまま入れる。答えが届いたら、議事録の「推測」を外し、置き場の `CLAUDE.md` にも反映してから保留を外す。

**会議の後の会話も議事録に足す**: 議事録を書いた後に、利用者と話して分かったことや決めたことは、その議題の「会議の後に分かったこと」に足す。会議で出た発言と混ぜないのは、後で読む人が「会議で合意したこと」と「後で調べたこと」を取り違えないため。

コミットはしない。利用者に言われたときだけする。

## 5. 振り返り

利用者が `/re` で振り返ったら、議事録の取り方で決まったことはこのスキルに、会議ごとのこと（参加者、語）は置き場の `CLAUDE.md` に書く。このスキルは公開のリポジトリにあるので、顧客名、会社名、人名、案件名は書かず、「ある会議で」と書く。

## Gotchas

- **話者の記号は会議をまたいで使えない**: xlisten は起動のたびに A・B… を振り直す。前の会議の対応をそのまま使うと別人に当たる。毎回、役割と発言の中身から当て直す
- **画面共有の資料は文字起こしに入らない**: 「この列」「F 列」のように画面を指す話は、何を指すかが文字起こしだけでは分からない。分からなければ、分からないと書く
- **はじめの数行は決まり文句の誤認識が多い**: 無音から whisper が「ご視聴ありがとうございました」を書く。議事録には入れない
- **「【会議の時刻】」が届いたら、始めるかを聞く前に `date` と比べる**: 1 回だけの cron でも、セッションが止まっていたり別の作業で埋まっていたりすると、知らせは時刻を過ぎてから届き、翌日になることもある。知らせの日付が今日でなければ、その会議は終わっている。開始から大きく過ぎていれば、始めるかを聞かずに過ぎた知らせとして伝える
