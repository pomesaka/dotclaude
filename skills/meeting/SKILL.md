# meeting

会議 1 回ぶんを、始める → 聞く → 止める → 議事録を書く、の順に進める。音を聞いて文字起こしを読む部分は listen スキルの手順に従い、このスキルはその前後と、議事録の中身を受け持つ。

議事録のリポジトリに固有のこと（定例の一覧、置き場の名前、知らせの出し方）は、そのリポジトリの `CLAUDE.md` にある。どの会議か（置き場）は、引数か「【会議の時刻】」の文から決める。

## 1. 始める

1. `AskUserQuestion` で、始めるかと入り口を聞く。選択肢は `web`（Meet や Slack のハドル）、`mic`（対面）、`今日はやらない`。知らせは開始の 2 分前に出るので、利用者は会議に入る直前に押す
2. `/listen <web|mic>` で聞き始める。別の会議の xlisten がまだ動いていると listen の起動が「起動に失敗」で知らせるので、止めてよいかを聞き、止めたらその会議の議事録を書いてから次へ進む
3. 聞き始めたら次を読む。会議中に話者や聞き違いを当てるのに使う
   - 置き場の `CLAUDE.md`。親のディレクトリにもあれば両方（例: `<相手>/CLAUDE.md` と `<相手>/<会議>/CLAUDE.md`）。参加者、役割、聞き違えやすい語が書いてある
   - 同じ置き場の前回の議事録の「宿題」と「未決」
   - 直前の会議を受ける会議なら、その日の直前の会議の議事録（例: 取引先との定例の直後に開く内部のキャッチアップなら、その日の取引先との定例の議事録）
4. 置き場のディレクトリが無ければ作る。定例でない会議は相手ごとのディレクトリに置く
5. ホワイトボードを用意して、ブラウザで開く（下の「ホワイトボード」）

## ホワイトボード

会議中、話の中身をローカルのホワイトボード（xwb）に書き足していく。発言を時系列で並べず、論点、決まったこと、宿題、未決を付箋に、仕組みや比較を図にする。Artifact には出さない（pomesaka の指示。社外の会議の中身を claude.ai に置かないため）。

xwb の使い方（何で描くか、付箋の色と欄、ボードの組み立て、進め方、SVG、コメントへの返事、守ること）は `/xwb` スキルに従う。ここには会議に固有のことだけを書く。

- **ボードは会議の種類ごとに 1 枚を使い続ける**: `<置き場>/<置き場の最後の名前>.board.json`（例: `<相手>/<会議>/<会議>.board.json`）。無ければ `xwb open <ボード> --title "<会議の名前>"` で作る。定例は宿題と未決が次の回へ持ち越されるので、毎回まっさらだと前回の分を描き直すところから始まる（pomesaka の判断）。定例でない会議は、相手ごとに 1 枚
- **ボードは「いま」だけを見せる**: ボードは会議中に流れを追うためのもので、記録は議事録が持つ。1 つの議題の付箋は、問いと結論のほかに 4 枚まで（根拠と、決定・未決・宿題）。減らすときは事実の付箋からまとめ、決定・宿題・未決の付箋は消さない（まとめの帯は付箋の `status` から集めるので、結論の欄に移すと帯から消える）。細かい事実は議事録に書く。種類ごとに 1 枚を使い続けるので、文字起こしの粒度で書くと 1 回で付箋が 60 枚を超え、数回で読めなくなる
- **まとめの帯**: xwb の `summary` の要素を 3 本（`show` が `decided`・`todo`・`open`）、ボードの一番上に置く。帯は付箋の `status` から集まるので、帯に付箋を手で写さない。議題のセクションは、いちばん高い帯の下に 60 空けて置く（帯の行が増減すると xwb が下を同じ量だけ動かす）。どの議題にも入らない宿題と未決は「そのほか」のセクションに置く。議事録の決定と宿題は `xwb summary <ボード>` の JSON から写す
- **議題のセクション**: 日付でなく話題ごとに置き、同じ話題は前の回のセクションに書き足す。題名は話題の名前だけにし、「議題 1」のような番号のラベルを付けない（pomesaka の指示）
- **話題の種類が決まっている定例は、セクションの骨組みを先に作る**: 置き場の `CLAUDE.md` にボードの軸（列の分け方、別のボードに分ける話題）が書いてあれば、聞き始める前にその形で用意する。話題が行き来する会議で話題の順に並べると、どこに何があるかが分からなくなり、会議の途中で並べ直すことになる。軸が書いていない定例で同じことが起きたら、利用者と決めた軸を置き場の `CLAUDE.md` に書く。列の見出し（軸の名前の文字）は、列の先頭のセクションのすぐ上（間 40 以内）に置く。離すと、`xwb format` が見出しを列と一緒に動かさない
- **xwb の欄を使って、座標と見た目を xwb に任せる**: 座標の計算、はみ出しの直し、見出しの手書きに、書き足しの手間の多くを取られていたため
  - `xwb check` にいつも `--style` を付ける。付けないと崩れ（重なり、はみ出し）しか出ず、欄の書き方の指摘（`handwritten-field`、`open-question`、`overdue`、`manual-summary` など）が出ない
  - セクションは `cols` を付けて作る（議題は `w: 760` で 3 列）。中身は `--in` で足し、`x`・`y` を書かない
  - 議題のセクションには、作るときに `question`（何を決める場か、問いの形で 1 文）を書き、決まったら `answer` に決まったことを 1〜2 文で書く。経緯のうち結論の根拠になるものだけを付箋に置き、残りは議事録に書く。会議の終わりに `open-question` の指摘を見て、結論を書くか、未決の帯へ移す
  - 付箋の欄は `/xwb` スキルの「付箋の欄」に従う。`status` には `decided`・`open`・`todo`（宿題）・`priority` を使う。`who` は名前だけにし、役割は中身から読み取れないときだけ付ける。会議中にサブエージェントで調べたことの付箋は `color: "teal"` と `tag: "調べた"` にする（/xwb スキルでは白だが、会議のボードでは発言の付箋と見分けたいため。pomesaka の指示）
  - 宿題は `status: "todo"` と、期限が出たら `due`（`YYYY-MM-DD`）で書く。見出しは、誰かが次にやることを動詞で書く（「仕様書を送る」）。「仕様書を求められた」のような起きたことは書かない。まとめの帯の ToDo の行には見出しが出るので、帯を読めば次に何をするかが分かるようにする（pomesaka の指摘）。宿題が終わったら付箋を消す
  - 前の回から持ち越した宿題と未決は、付箋を残して `status`（`todo` か `open`）のまま `carriedFrom` に元の回の日付（`YYYY-MM-DD`）を書く。セクションの `answer` や本文に「11/11 から持ち越し」と書かない。持ち越す議題の `answer` は「未決。次の回で話す」のように、いまの状態だけを書く
  - 意見が 2 つに割れた議論は `xwb template` の `versus`、2 つの軸で分けられる話は `matrix`、論点や原因の分解は `tree` で描く。白い付箋に賛否を混ぜて並べない
  - 議題が移ったら `xwb focus <ボード> <セクションの id>` でそのセクションを目立たせ、会議の終わりに `xwb focus <ボード>` でやめる
- 文字起こしの聞き違いは、置き場の `CLAUDE.md` の語で直して書く
- **画面で共有している資料は、文字起こしより確かな情報源として扱う**: 聞き始めたら、画面で共有している資料（議題の表など）があるかを利用者に聞き、あればスクショをもらう。資料は文字起こしに入らず、「この列」「F 列」のように画面を指す話は、資料が無いと何を指すか分からない。分からなければ、分からないと書く。語や数値が文字起こしと資料で食い違ったら資料を正とし、それまでのボードと議事録の事実も資料に合わせて直す。スクショは表やガントにしてボードに足し、中身を写し終えたら PNG は消す（pomesaka の指示）。画像を貼るのは、図や見た目そのものが中身のときだけにし、1 か所の資料の枠にまとめず、それを使う議題のセクションの中に置く
- **書き足しはサブエージェントに任せる**: 議題が変わったとき、何かが決まったとき、または前回から 5 分たったときに、Agent を `subagent_type: "xwb-write"`、`run_in_background: true` で立てる。毎回メインで書くと、会議 1 時間ぶんの書き換えでメインの文脈が埋まるためだ。書き手の決まり（xwb の欄を使う、付箋の数、資料に無い説明を足さない）は xwb-write の定義にあるので、頼む文に写さない
  - 渡すのは、ボードのパス、文字起こしの `events/` のパス、置き場の `CLAUDE.md` のパス、前回どこまで読んだか（`at`）。前回の書き足しの後に調べた結果が届いていれば、その要点と出典も渡す
  - 返ってきた `at` を、次の書き足しに渡す。前の書き足しが戻る前に次を立てない。同じボードに 2 つが同時に書くと、同じ行を二度書く
  - 報告やボードに固有名詞の説明があれば、メインで文字起こしか資料に出典があるかを確かめてから残す。書き手は、聞き取れていない固有名詞にもっともらしい説明を付け足すことがあり、ボードでは事実と見分けが付かなくなる
- 利用者がボードについて頼んだこと（「この話を図にして」、コメント）は、メインで直す

## 2. 聞いている間

listen スキルの「聞いている間」に従う。会議の記録で足すことは次のとおり。

- **話者の対応を教えてもらったら、記録を 2 か所に書く**: `<出力フォルダ>/inbox.txt` に 1 行足し、新しい人や役割は置き場の `CLAUDE.md` に足す。xlisten は起動のたびに記号（A・B…）を振り直すので、前の会議の対応をそのまま使うと別人に当たる。置き場の `CLAUDE.md` には記号ではなく、役割と話し方（進行役、質問を持ち込む人）を書き、毎回それと発言の中身から当て直す
- **聞き違えやすい語が分かったら、置き場の `CLAUDE.md` に足す**: 社名、製品名、システム名。次回の議事録で最初から正しく書ける
- **参加者が困っていたら、頼まれる前に調べる**: 「分からない」「調べないと」「どうなんだろう」「なんとも言えない」と、会議で答えが出ずに止まったら、listen スキルの手順で `research` のサブエージェントに調べさせ、結果を pomesaka に伝える。結果は次の書き足しで xwb-write に渡し、ボードに置かせる。会議中に pomesaka が参加者へ渡せるようにするため（pomesaka の指示）
- **利用者の「？」には議論で答える**: 会議の内容への質問（「何が問題になってる？」「〜どう思う？」）には、文字起こしから流れをまとめて答え、意見を言う。意見の前提が推測なら推測と書く
- **会議の発言に事実の誤りがあれば、そっと補足する**: 利用者にだけ見える形で、1〜3 行で書く。会議を止めさせるためではなく、利用者が後で確かめるため

## 3. 止める

利用者が「終わり」「おわり〜」などと言ったら止める。議事録が要るかは聞かない（毎回書く）。

1. listen スキルの「止める」の手順で xlisten を止める。`stop.sh` が、Monitor にまだ届いていない最後の 1 分ぶんの行も出す
2. 次の会議がすぐ続くなら（リポジトリの `CLAUDE.md` の定例の一覧に書いてある）、議事録を書く前に、次の会議を始めるかを聞く。時刻の知らせを待たない。二重にならないよう、その会議の時刻の知らせは `CronDelete` で消す
3. ボードの最後の書き足しを済ませる。整理は「5. 仕上げ」でする

## 4. 議事録を書く

形は [template.md](template.md) に従う。ボードと文字起こしの両方から書く。ボードで決まったことや宿題として書いたものは、議事録でも同じ言葉にする。

- 書く前に `xwb changes <ボード>` で、利用者がボードに書き足したり直したりした付箋を読み、議事録に入れる。入れ終わったら `--clear`
- ファイルは `<置き場>/YYYYMMDD.md`。同じ日に同じ会議が 2 回あれば `YYYYMMDD-2.md`
- 議事録を人に渡す会議では、書き始める前に、渡す先の分け方（会議ごと、製品ごと）とファイルの名前を確かめて合わせる。置き場の `CLAUDE.md` に渡し方が書いてあればそれに従い、書いてなければ利用者に渡す先と既存のファイルの名前を聞いて、置き場の `CLAUDE.md` に書く。書いた後に分け方が違うと分かると、議事録を分け直し、名前を付け直すことになる
- 終わった時刻は `date` で取る

**推して書いたところは、会議中は保留に残し、仕上げで pomesaka に直接確かめる**: 話者、聞き違えた名前、担当。`mcp__questions__add_question` の `detail` には、根拠の文字起こしの行をそのまま入れる。答えが届いたら、議事録とボードを答えに合わせて直し（ボードの「（聞き取り）」と相対の日付も直す）、置き場の `CLAUDE.md` にも反映してから保留を外す。ボードは次の回も使い続けるため。

**会議の後の会話も議事録に足す**: 議事録を書いた後に、利用者と話して分かったことや決めたことは、その議題の「会議の後に分かったこと」に足す。会議で出た発言と混ぜないのは、後で読む人が「会議で合意したこと」と「後で調べたこと」を取り違えないため。

コミットはしない。利用者に言われたときだけする。コミットしたら、その回の文字起こしのフォルダとログ（`~/.claude/tmp/xlisten/`）を `rm -r` で消す。会議の生の発言が残らないようにするため（pomesaka の指示）。

## 5. 仕上げ

議事録を書き終えたら、pomesaka に渡す前に、議事録とボードを外の人にそのまま見せられる形にする。注記の残った議事録と、片付いた議題の残ったボードを渡すと、pomesaka に言われてから直すことになる。

1. **分からないことを pomesaka に直接聞く**: 「4. 議事録を書く」で保留に残したもの（推した話者、聞き違えた名前、担当）と、中身の分からなかった項目を、`AskUserQuestion` でまとめて聞く（1 回に 4 問まで。選択肢は推した答えとそれに次ぐ候補）。答えで議事録とボードを直し、残っていた保留は外す。聞いても分からないものは、議事録とボードから外す（「聞き取れず」と書いて残さない）。保留の一覧に置いたまま渡さない（pomesaka の指示）
2. **ボードを整理する**: 結論が出て、開いた宿題も未決も残らない議題のセクションは消す（決定は議事録にある）。残す議題は付箋を 4 枚までにする。本文の言い回しを議事録にそろえ、`xwb format <ボード>` で並べる。置き場の `CLAUDE.md` が PNG を残すとしていれば、`xwb shot <ボード> --scale 1` で `<置き場>/YYYYMMDD.board.png` に保存する
3. **`finish.sh` で確かめる**: `${CLAUDE_SKILL_DIR}/finish.sh <議事録> <ボード>` を実行する。議事録の作り方の注記、冒頭の表の「記録」「話者」の行、相対の日付、言い換える語、ボードの `xwb check --style` の指摘、ボードの「（聞き取り）」、宿題の数のボードと議事録の食い違いを出す。「仕上がっている」と出るまで直す。判断の要る直し（言い換え、消すか）は自分でする
4. 仕上がったら、議事録のパスと要点を伝える

## 6. 振り返り

利用者が `/re` で振り返ったら、議事録の取り方で決まったことはこのスキルに、会議ごとのこと（参加者、語）は置き場の `CLAUDE.md` に書く。このスキルは公開のリポジトリにあるので、顧客名、会社名、人名、案件名は書かず、「ある会議で」と書く。

## Gotchas

- **はじめの数行は決まり文句の誤認識が多い**: 無音から whisper が「ご視聴ありがとうございました」を書く。議事録には入れない
- **「【会議の時刻】」が届いたら、始めるかを聞く前に `date` と比べる**: 1 回だけの cron でも、セッションが止まっていたり別の作業で埋まっていたりすると、知らせは時刻を過ぎてから届き、翌日になることもある。知らせの日付が今日でなければ、その会議は終わっている。開始から大きく過ぎていれば、始めるかを聞かずに過ぎた知らせとして伝える
- **ボードや議事録の名前は、前の回の覚えや置き場に残るファイルでなく、このスキルの今の文面で決める**: このスキルは振り返りで同じ日にも書き換わり、置き場には前の決まりで作ったファイル（日付の名前のボードなど）が残っている。ボードやファイルを作る前に、その節を開き直して確かめる
