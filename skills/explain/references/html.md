# ブラウザで開くページ（HTML）

`explain`の出す先が「ブラウザ」のときに読む。何を説明するかは`SKILL.md`で決めてあるものとし、ここにはページの作り方だけを書く。

## ページを作る

2つのスキルを読み込み、役割を分けて使う。

| 決めること | 従うスキル |
|---|---|
| 資料の組み立て（冒頭の結論、見出しの1文、図の形、要点1行、畳むもの） | `figure-docs` |
| 色、書体、余白、テーマ、図の描き方の細部 | `artifact-design`（図があるなら`artifact-diagramming`も） |

2つが食い違ったら、組み立ては`figure-docs`を優先する。`artifact-design`だけを読むと、見た目は整っても、表や文章に頼った読みにくいページになる。このスキルから見た目の細部の指示はしない。

ローカルで開くので、claude.aiでの公開に関わる部分だけを置き換える。

- `<!doctype html>`から`</html>`までの骨組みは自分で書く（公開時に足される骨組みが無いため）
- 画面の幅いっぱいを使う。本文を`max-width`で囲まず、図と表は画面の幅に合わせて広げる。文の段落だけは、1行が長くなりすぎないように段落に`max-width`（60〜80字ほど）を付けてよい。pomesakaはデスクトップのブラウザで見て、スマホではほとんど見ない（pomesakaと確認）。読みやすい本文の幅に図まで収めると、広い画面で小さく縮んだ図になる。svgの座標の幅（viewBox）も、1400〜1600くらいの広さで描く
- Artifactツールでは公開しない。ページの中身をclaude.aiに保存しないためのスキルなので、利用者が明示的に頼んだときだけ公開する
- `artifact-design`の「公開前に1回見る」は、検査のスクリプトとheadlessのChromeのスクリーンショットで行う。先に検査を走らせ、挙がった所を直して0件にしてから撮る。検査は、狭い列での折り返し、はみ出し、SVGの文字の重なり、小さい文字、コントラスト、横に並んだ`<details>`、本文を狭く囲んだ幅を、幅1440pxと1920pxの明暗の両テーマで数えて見る。これらは撮った画像を見ても気づけず、人に言われるまで残った。誤検知と判断して直さない項目は、理由を返答に書く。画像では、検査が見ない、札と線の対応と図の読み取りやすさを見る。ブラウザが無い環境なら行わず、チャットの返答に「描画は未確認」と書く

  ```bash
  bun ~/.claude/skills/figure-docs/scripts/check-layout.ts <ページの絶対パス>
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=5000 --window-size=1280,1600 --screenshot=<ページと同じ場所>/<名前>.png file://<ページの絶対パス>
  ```

  `--virtual-time-budget`は、Webフォントが読み込まれるまで撮るのを待たせる。無いと代わりのフォントで撮られ、幅の違いで文字が切れて見える

- `~/.claude/tmp/explain/<内容を表す短い英数字とハイフン>.html`に書き、`open`で開く

## 決めてほしいことがあるとき

決めてほしいことが1つでもあれば、ページの上で答えてもらい、答えをチャットに貼り戻してもらう。問いが1つで選択肢が2つのときも同じにする。問いを本文の箇条書きやチャットだけで済ませない。

`explain`のスキルのディレクトリ（このファイルの1つ上）にある`question.html`が、そのための部品（問いのタブ、回答済みの印、答えを1つのテキストにまとめてコピーするボタン）。部品の先頭のコメントにある「残す2点」は変えないので、ページを書く前に部品を読む。どこに置くか、見た目をどう合わせるかは、そのページに合わせて決めてよい。

使わないのは、決めてほしいことが無いページだけ。

貼り戻されたテキストは、利用者の決定として扱って作業を続ける。

## チャットでの返答

ページのパスと、要点を1〜3文で返す。ページの中身をチャットに繰り返さない。決めてほしいことがあるときは、問いがページにあることと、その件数だけを書く。問いと選択肢をチャットに書き写さない。
