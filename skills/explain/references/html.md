# ブラウザで開くページ（HTML）

`explain`の出す先が「ブラウザ」のときに読む。何を説明するかは`SKILL.md`で決めてあるものとし、ここにはページの作り方だけを書く。見た目は`artifact-design`に任せる。

## ページを作る

上で決めた中身を材料にして、`artifact-design`スキル（図があるなら`artifact-diagramming`スキルも）を読み込み、その指示どおりに作る。このスキルから見た目の指示はしない。

ローカルで開くので、claude.aiでの公開に関わる部分だけを置き換える。

- `<!doctype html>`から`</html>`までの骨組みは自分で書く（公開時に足される骨組みが無いため）
- Artifactツールでは公開しない。ページの中身をclaude.aiに保存しないためのスキルなので、利用者が明示的に頼んだときだけ公開する
- `artifact-design`の「公開前に1回見る」は、headlessのChromeのスクリーンショットで行う。ブラウザが無い環境なら行わず、チャットの返答に「描画は未確認」と書く

  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1280,1600 --screenshot=<ページと同じ場所>/<名前>.png file://<ページの絶対パス>
  ```

- `~/.claude/tmp/explain/<内容を表す短い英数字とハイフン>.html`に書き、`open`で開く

## 決めてほしいことがあるとき

決めてほしいことが1つでもあれば、ページの上で答えてもらい、答えをチャットに貼り戻してもらう。問いが1つで選択肢が2つのときも同じにする。問いを本文の箇条書きやチャットだけで済ませない。

`explain`のスキルのディレクトリ（このファイルの1つ上）にある`question.html`が、そのための部品（問いのタブ、回答済みの印、答えを1つのテキストにまとめてコピーするボタン）。ページを書く前に必ず読む。どこに置くか、見た目をどう合わせるかは、そのページに合わせて決めてよい。部品の先頭のコメントにある「残す2点」は変えない。

使わないのは、決めてほしいことが無いページだけ。

貼り戻されたテキストは、利用者の決定として扱って作業を続ける。

## チャットでの返答

ページのパスと、要点を1〜3文で返す。ページの中身をチャットに繰り返さない。決めてほしいことがあるときは、問いがページにあることと、その件数だけを書く。問いと選択肢をチャットに書き写さない。

## Gotchas

- **`question.html`を「任意の部品」と読んで省かない**: 以前の文面は「貼り戻してもらう形にできる」「使うかどうかは決めてよい」で、決めてほしいことが3つあったページで部品を開かずに省き、箇条書きとチャットで済ませた（claude-deck・2026-10-09）。任意と読める文面で手間に差があると、短いほうを選んでしまう。判断基準: 「このページに、利用者に選んでもらう問いが1つでもあるか？」YESなら部品を使う
