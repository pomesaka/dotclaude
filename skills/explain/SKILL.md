# explain

利用者本人が読むための説明を作る。このスキルが決めるのは「何を、どの順で説明するか」と「どこに出すか」で、描き方は出す先ごとの参照ファイルに分けてある。

会話の中で決まったことや調べたことを材料にするので、`context: fork`にはしない。

出す先を決めて呼ぶ入口が3つある。どれも、このスキルの手順で中身を決める。

| 入口 | 出す先 |
|---|---|
| `/explain` | 下の「出す先を選ぶ」で決める |
| `/explain-inline` | 会話の中 |
| `/explain-pane` | pane |
| `/explain-html` | ブラウザのページ |

## 何を説明するかを決める

書く前に次を決める。説明の種類ごとの型は持たない。

1. **読み終えた後に、読み手は何をするか**: 案を選ぶ、PRをレビューする、実装に入る、理解して終わる、など
2. **読み手がまだ知らないことは何か**: 下の「読み手の前提を見積もる」で決める
3. **決めてほしいことは何か**: あれば、問いと選択肢と、おすすめとその理由まで決める

## 読み手の前提を見積もる

説明が伝わらない原因は、たいてい、書き手だけが知っている前提を読み手も知っていると思い込むことだ。長く作業したセッションほど起きる。作業の途中で覚えた語、節の番号、略語、実験の名前は、書き手には当たり前になっているが、利用者は見ていない。

次の2つに分けて考える。

| 利用者が知っていること | 利用者が知らないこと |
|---|---|
| 利用者が自分で会話に書いたこと | Claudeがツールの結果や文書から知ったこと |
| 普段使っている道具、扱っているプロジェクトの目的 | Claudeが作業の途中で付けた呼び名、読んだ仕様の節の番号や略語 |
| CLAUDE.mdに書いてある決まり | サブエージェントや別の会話が調べたこと |

左は説明しない。右は、初めて出すときに1文で説明するか、ふつうの言葉に言い換える。判断基準: 「この語は、利用者が自分で打ったか？」打っていなければ、説明なしに使わない。

利用者が「全体像が分からない」「仕組みが分からない」と言ったら、選択肢の説明を足すのでなく、1段上から書き直す。

## 説明の順番

上から下へ、次の順で書く。前の段が分からないと次の段が読めないときは、前の段を省かない。

1. **全体**: いま何を作っていて、それはどういう仕組みで動くか。登場するもの（送る側、受ける側、あいだに入るもの、など）と、その関係。図にできるなら図にする
2. **論点の場所**: その仕組みのどこで、何が問題になっているか
3. **選択肢か結論**: 何を選べるか、選ぶと何が変わるか。仮に決めてあるなら、その理由
4. **分かっていないこと**: 確かめていない点

読み手がすでに1と2を知っているなら、3から始めてよい。迷ったら、1を2〜3文と図1つで入れる。

保留（`questions`のMod）の説明は、利用者が見ていない作業の中で出た問いなので、1から書く。

## 根拠を付ける

- コードについての主張には、ファイルのパスと行番号を書く
- 外部のサービスやライブラリの仕様には、公式ドキュメントへのリンクを付ける
- 確かめていないことは「未検証」と書く。もっともらしい数字（料金、上限、性能）を推測で埋めない
- 説明のために作った例（回答の見本、架空のデータ）は、作った例だと書く
- 本文の日本語は`~/.claude/docs/japanese-writing.md`に従う

## 出す先を選ぶ

入口で決まっていなければ、次で選ぶ。決め手は、長さと、読んだあとも要るか。

| 出す先 | 使う場面 | 読む参照 |
|---|---|---|
| 会話の中 | 1画面に収まり、読んでその場で答えて終わる。迷ったらこれ | `references/rich.md` |
| pane | 横に出したまま会話や作業を続ける。作業の計画、議論している構成の図 | `references/rich.md` |
| ブラウザ | 2画面を超える、斜めの線や多くの箱が要る図、あとで見返す | `references/html.md` |

**出す先を決めたら、その参照ファイルを読んでから描く。** 参照ファイルは、このスキルのディレクトリにある。

- ファイルを書けない会話（保留の相談用に分岐した会話など）では、会話の中に出す。ブラウザのページは作れない
- `mcp__rich__show`が一覧に無いセッションでは、ブラウザに出すか、文章で答える
- 会話の中に収まらないと分かったら、詰め込まずに、タブに分けるか、ブラウザに変える

## 決めてほしいことがあるとき

問いは、説明と同じ場所に置き、クリックで答えられるようにする。本文の箇条書きやチャットだけで済ませない。置き方は出す先ごとに違うので、参照ファイルに従う（会話の中とpaneはカードか質問のボタン、ブラウザは`question.html`の部品）。

届いた答えは、利用者の決定として扱って作業を続ける。
