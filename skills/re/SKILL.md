# Retro (Retrospective)

作業セッションの振り返りを行い、「次に活かせる発見」を適切な場所に書き出す。

## フロー

### Step 1: 発見の抽出

会話ヒストリーを振り返り、以下の観点で発見を抽出する:

- **Gotchas**: 詰まった箇所・意外な落とし穴・次回繰り返さないための注意点
- **設計判断**: なぜそのアプローチを選んだか（却下した代替案があれば）
- **スキル・フローの改善点**: 今回のフローで「次はこうしたい」と感じたこと
- **プロジェクト固有ルール**: このプロジェクトだけに適用されるべき制約・規約
- **hook 化できる繰り返し作業**: ファイル編集後に毎回手動で実行しているコマンド（lint・typecheck・format・test など）。静的に実行できるものは hook で自動化するとエージェントの作業効率が上がる

発見のない観点は省く。「会話の要約」は書かない — **次に活かせるもの**だけ残す。

### Step 2: 書き先の判断

各発見について最適な記録先を判断する。

| 内容 | 優先する書き先 |
|------|---------------|
| スキル固有の落とし穴・改善 | そのスキルの `Gotchas` セクション末尾 |
| プロジェクト規約・アーキテクチャ制約 | `docs/conventions.md` または `docs/architecture.md` |
| 設計上の意思決定（Why + 却下案） | `docs/adr/` または `docs/architecture.md` |
| グローバルに使えるパターン・Tips | `~/.claude/docs/<topic>.md`（新規 or 既存に追記） |
| Claude の振る舞い・ユーザーの好み | memory（feedback / user type） |
| 一時的・このセッション限りの情報 | スキップ |
| 毎回手動で実行している静的チェック（lint・typecheck・format 等） | `update-config` スキルで hook として設定することを提案する |

**書き先の選択基準**:
1. このプロジェクト固有か？ → プロジェクト側（`docs/` or プロジェクト `CLAUDE.md`）
2. 他のプロジェクトでも起きうるか？ → グローバル（`~/.claude/docs/`）
3. Claude の挙動を変えるべきか？ → memory
4. スキルのフローに問題があったか？ → スキルファイルの `Gotchas`

書き先が不明な場合は AskUserQuestion で確認する。

**プロジェクト内の書き先確認**: `docs/` が存在するかを `fd --type d --max-depth 1 docs` で確認してから判断する。

### Step 3: 書き込み（確認なし）

発見と書き先が決まったら、ユーザーの確認を待たずに直接書き込む。
発見が0件の場合は「特筆すべき発見はありませんでした」と伝えて終了する。

書き込み時のルール:
- **既存ファイルへの追記**: `Gotchas` セクションなら末尾に `- **[タイトル]**: ...` 形式で追加
- **新規ファイル**: kebab-case で作成。frontmatter は不要（`~/.claude/docs/` 以下は prose で書く）
- **memory**: 会話の memory システムに書き込む（feedback / project / user type に応じて）
- **docs/ への追記**: 既存セクションに自然につながるよう挿入する

書き込み後、何をどこに書いたか1行ずつ箇条書きで報告する。

## Gotchas

- **hook 化の判断基準**: `PostToolUse` hook で自動実行できるのは「毎回・全ファイル・副作用なし」の静的チェックのみ。`lint`・`typecheck`・`format` は適している。テストは重くなりすぎるので不向き。hook 化の提案は `/update-config` スキルに委譲する
- **要約と振り返りは違う**: 「何をやったか」の記録は不要。「次回どう動くべきか」の知見だけ抽出する
- **量より質**: 5件の薄い発見より1件の深い発見の方が価値がある。迷ったらスキップ
- **スキルの Gotchas は具体的に**: 「問題があった」ではなく「〇〇すると△△になる。対処: □□」の形式で書く
- **プロジェクト CLAUDE.md への追記は慎重に**: 既存のルールと重複・矛盾しないか Read で確認してから追記する
- **`disable-model-invocation: true` を設定すると Skill ツール経由の呼び出しも封じられる**: update-pr などから `Skill("re")` で呼ぼうとしてもブロックされる。他スキルからチェーンで呼ばれる可能性があるスキルには設定しない
