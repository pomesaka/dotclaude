# PMが決めること、利用者に聞くこと

確認待ちで作業が止まらないように、クリティカルでない判断はPMが決める。始めるときに利用者に確かめた範囲を、こちらより優先する。

## PMが決めてよいもの

- 担当の案（まとめ方、テストの形、直す順番の細部）
- 実装の細部の既定値で、旗や設定で変えられるもの
- ゆらぎの直し方、検査の足し方
- CIが通り、レビュー済みのPRのマージ（権限をもらっているとき）

決めたら、決めた内容と理由を報告に書く。

## 利用者に聞くもの

- プロジェクトの方向を変えるもの（採用する技術や仕様の版、範囲の拡大と縮小）
- 認証、認可、安全性の方針。待ち受けるアドレスや、トークンを既定で求めるか
- デプロイ、ログ、保存期間、ライセンス、公開、費用が発生するもの
- 戻せない操作
- プロジェクトの未決事項の一覧に載っている項目

聞くものは、保留の一覧に足して、仮の選択肢で先へ進める。仮置きの上に立つPRはマージしない。

## 担当の判断を確かめる

担当は、自分の作業の範囲で既定を決めてくることがある。PMは次の形を見つけたら止める。

- **誤った設定で、黙って緩い側に倒れる:** 鍵やトークンの設定が誤っているときに「無いのと同じ」に扱う形。止まるか誤りを返す形にさせる
- **断るときに何も答えない:** 相手が時間切れまで待つ。断ったことが分かる形で必ず答えさせる
- **デモや試験の名前を、部品の既定値に持たせる:** 設定が無ければ空にし、デモの側から明示して渡させる
