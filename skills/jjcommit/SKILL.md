# Jujutsu Commit

現在の変更をコミットして新しい空のリビジョンを作成する。

## 最近のログ

!`jj log --limit 3`

## 手順

### 1. 変更内容を確認

`jj diffu` を実行して現在のリビジョンの変更内容を確認する。

### 2. WHYを会話ヒストリーから収集

diffからはWHAT/HOWしか読み取れない。WHY（なぜ変えたか）は会話ヒストリーにしかない。
以下を特定する。

- **課題・動機**: 何を解決しようとしていたか
- **設計判断の理由**: なぜこのアプローチか、却下した代替案とその理由
- **背景情報**: バグの根本原因、制約、要件

集めたWHYのうち、変更が終わった後もそのコードを読む人に要るもの（実装の理由、外部の制約、意図的な非対称）は、コミットメッセージだけに書かず、コードコメントに入っているかを確かめる。入っていなければ、コミットの前に利用者に伝える。置き分けの基準は`~/.claude/docs/what-goes-where.md`にある。

### 3. コミットメッセージを作成・実行

WHY（Step 2）とWHAT（Step 1）からメッセージを作成し、`jj commit` で実行する。

```bash
jj commit -m "$(cat <<'EOF'
<タイトル (50文字以内)>

<WHY - 背景と動機>
- なぜこの変更が必要だったか
- 選んだアプローチとその理由

<WHAT - 主要な変更内容>
- 変更点の説明

🤖 Generated with [Claude Code](https://claude.ai/code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
)"
```

### 4. 確認

`jj log --limit 2` でコミットを確認。

## ガイドライン

- コードベースの言語に合わせる（日本語のコメント/ドキュメントなら日本語）
- WHYを主軸にする（WHATはdiffから読める）
- メッセージだけで変更の意図が理解できるレベルの具体性

## Gotchas

- **diffに独立した関心事が混ざっていたら、コミットする前に分ける**: 作業コピーの全体を1つのコミットにすると、後でレビューで分割を求められ、手でやり直すことになる。作業コピーには、別のセッションの変更や、同期された生成物が混ざっていることもある。`jj commit <パス>`で関心事ごとにコミットし、どれにも属さないものは作業コピーに残す。
- **diffが大きくて出力が別のファイルに退避されたら、そのファイルをReadしてから書く**: `--stat`や先頭の数百行だけを見て「全体を確認した」と書いたことがある。ファイルごとの要約は、そのファイルの差分を読んでから書く。読んでいない部分があるなら、そう書く。
- **文の中に書かれた`/jjcommit`は起動しないことがある**: 「おk、/jjcommit」のように文に混ぜて送られると、スキルが読み込まれないことがある。このスキルは`disable-model-invocation: true`なので、Skillツールで呼んでも拒否される。手順を手で再現せず、利用者に`/jjcommit`だけを単独で送ってもらう（2026-09に確認）。
