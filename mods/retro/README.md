# retro

reのスキル（振り返り）を、裏で自動に回すMod。利用者が「振り返って」と頼まなくても、次に活かせる発見を控えに数え、くり返し出たものを文書に書く。メインのClaudeには何も送らず、メインのターンも使わない。

## 振り返り方

3段に分けて、重い3段目は文書に上げる発見があるときだけ動かす。

| 段 | すること | 重さ |
|---|---|---|
| 1. 発見を聞く | 会話を分岐させ（`$.model.fork`）、次に活かせる発見を3つまでJSONで返させる。このセッションですでに挙げた見出しと、控えの見出しも渡す。発見ごとに、種類（文書で防ぐか、仕組みで防ぐか、スキルやエージェントへの要望か）、1回でも害が大きいか、控えのどれと同じかを答えさせる。間違いでなくても、使ったスキル、エージェント、Modが使いにくかったら、要望として挙げさせる | 1回の応答。メインの要求のキャッシュを使う |
| 2. 控えに数える | Modのコードが、発見を控えに足すか、同じ控えの回数を1つ増やす。文書の発見が2回目に出たとき、または1回目でも害が大きいときだけ、3段目に回す。仕組みの発見と要望は、何回出ても文書に回さない | モデルを呼ばない |
| 3. 文書に書く | 会話を持たないサブエージェント（`general-purpose`、モデルはメインと同じ）を裏で立て、上げる控えだけを、回数と根拠を添えて渡す。エージェントは`skills/re/SKILL.md`のStep 2〜4に従い、既存の項目を探して言い方を直すか、新しく書く | ファイルを読んで探す往復。会話は送らない |

控えを挟むのは、1回きりの事故から書いた規則が積み重なって、大事な文が埋もれるためだ。自動の振り返りを始めた後、11-16からの3日で、よく読む文書が1.5倍になった。仕組み（hook、lint、スクリプト、Mod、環境の設定の直し）で防げる発見は、文に書くより仕組みにしたほうが確実に効くので、文書に書かずに作る候補として控えに残す（2026-11-19にpomesakaと決めた）。

要望（スキル、エージェント、Modの使いにくさ）は、対象の名前と一緒に数える。直すのは、作りを書き換えられるdotclaudeのセッションで、`dotclaude-sync`のpushの後に、まだ外していない要望が回数の多い順に出る。直したら`/retro drop`で外す。文書の書き手に回さないのは、書き手は注意書きを足すことしかできず、決まりやエージェントの出力の形を作り直せないためだ（2026-11-19にpomesakaと決めた）。

控えは、出来事（発見が出た、文書に上げた、外した）を`~/.claude/retro/<セッションID>.jsonl`に1行ずつ足して持ち、読むときに全セッションのファイルをatの順に束ねる。1つのファイルを書くのは1つのセッションだけだ。前の版は`$.store`の1つのキーに持っていたが、同時に振り返った2つのセッションが読んで書き戻すと、片方の回数が上書きで消えた。ファイルはリポジトリの外に置く。根拠に案件の名前や作業ディレクトリが入るためだ。前の版の控えは、ファイルがまだ1つも無いときに1度だけ移す。控えは100件までで、回数の少なく古いものから落とす。文書に上げた控えは回数を0に戻して残す。文書にした後でまた2回出たら、文では防げていないので、もう一度上げる。書き手は、まず型、テスト、lint、hook、スクリプトで止められるかを確かめ、小さく作れるなら文を直す代わりに作って、その間違いで落ちることを確かめる。作れなければ文を直す。

書き手に会話を持たせないのは、ツールを使うたびに会話の全部を送り直さないためだ。会話を引き継いだフォークで書かせると、往復の数だけ会話の全部を読むことになる（2026-11-13に利用者と決めた）。

書き手が終わると、toastで知らせ、何をどこに書いたかを`/retro log`で読めるようにする。書き手の報告はメインに届けない。届くとメインが1ターン動いて、書いた内容を報告し直すからだ。報告は2つの形で届く。報告用のツールで送った報告（`<agent-message from="ID">`）と、終わった知らせ（`<task-id>ID</task-id>`）だ。どちらも、書き手のIDが付いていれば止め、報告の本文を`/retro log`に残す。会話の行には「Prompt dropped by a hook: retro の書き手の報告（/retro log で読める）」が1行出る。報告用のツールで送った報告を止められるかは、実機ではまだ確かめていない。

## 振り返る時点

Modは、最後に振り返った後のメインのターン、利用者が直した発言、止まったターンを数える。モデルを呼ばずに数え、次のどれかに当たったときだけ1段目に進む。

| きっかけ | 条件 |
|---|---|
| compactの直前 | 3ターン以上たっている。compactの後は会話が要約に置き換わるので、出来事を問わない。聞き終わってからcompactに進む |
| コミット、push、PRの作成やマージ | そのターンが答えて終わり、10ターン以上たっている |
| 道具を多く呼んだターン | そのターンが答えて終わり、メインが道具を8回以上呼び、3ターン以上たっている。分岐には呼んだ回数を渡し、毎回同じで判断の要らない手を探させる（置き場は`docs/agent-environment.md`の順番） |
| 一定のターン数 | 答えて終わったターンで、20ターン以上たち、そのあいだに直された発言か止まったターンが1つ以上ある |
| `/retro` | いつでも。自動がOFFでも動く |

- **直した発言:** 入力欄から送った文が「違う」「なんで」「いや、」などで始まるか、「じゃなくて」「って言った」などを含む。粗い判定で、拾いすぎても1段目の1回で済む。next-stepの札から送った文は数えない
- **止まったターン:** 答えて終わらなかったターン（中断、エラー）
- **数を戻す時点:** 1段目が答えたとき。発見が無くても戻す。答えられなかったら戻さず、次のきっかけで聞き直す

数えるのはメインのターンだけで、サブエージェントのターンと、サブエージェントが走らせたコミットは数えない。

## コマンド

| コマンド | 動き |
|---|---|
| `/retro` | いま振り返る |
| `/retro off` | このセッションの自動の振り返りを止める |
| `/retro on` | 自動の振り返りを戻す |
| `/retro log` | 書き手の報告を、新しい順に10件まで出す |
| `/retro candidates` | 控えを、回数の多い順に出す。仕組みの候補と要望から、作るもの、直すものを選ぶのに使う |
| `/retro drop <id>` | 控えを1件外す。仕組みを作った後、要望を直した後か、要らないと決めたときに使う |

既定はONで、セッションごとに切り替える。`re`という名前のスキルがあるので、コマンドの名前は`retro`にした。スキルと同じ名前のコマンドは呼べない。

## 覚えているもの

自動がONかどうか、数えている出来事、挙げた発見の見出し（40件まで）、書き手の報告（10件まで）を、`$.store`にセッションごとに持つ（キーは`session:<セッションID>`）。覚えておくのは30セッションまで。控えは、上の「振り返り方」のとおり、セッションをまたいで持つ。

## 開発

```bash
claude plugin validate mods/retro
claude plugin test mods/retro
```
