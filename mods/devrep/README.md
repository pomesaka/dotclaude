# devrep

ONにしたセッションで、Claudeが作業の状況を書いてpaneに置いておくMod。しばらく離れていたセッションに戻ったとき、会話を読み返さずに、いま何をしていて、次に何をするかが分かる。

```
[閉じる] [更新を頼む] [OFFにする]
3時間前に更新 +2

いま（2026-10-10 23:05）
帯の幅の計算を直している

次にすること
1. テストを足す
2. READMEに反映する

待っていること
-  幅のしきい値を決める

決まったこと
-  表は使わない
```

## ONとOFF

既定はOFFで、セッションごとに切り替える。OFFのセッションでは、Claudeに説明を渡さず、催促もしない。質問に1回答えて終わるようなセッションで、状況を書かせないためだ。

| ONにする操作 | 最初の状況が書かれる時点 |
|---|---|
| Claudeに「作業の状況を書いておいて」と頼む | その場。ツールが呼ばれるとONになる |
| paneの「ONにする」（`o`） | その場。Modが、書くようClaudeに頼む文を送る |
| `/devrep on` | 次のプロンプトのターン。コマンドのhookからは文を送れないので、Claudeだけが読む文として渡す |

OFFにするのは、`/devrep off`かpaneの「OFFにする」（`o`）。書いてある状況はpaneに残る。

## 状況の中身

Claudeが`update_devrep`ツールを呼ぶと、全体が置き換わり、paneに出る。フォーカスは移さない。

| 項目 | 中身 |
|---|---|
| `now` | いましていること。必須 |
| `next` | 次にすること。取りかかる順に1〜6個。必須 |
| `sections` | そのほかの節。見出しと項目（1〜6個）の組を、6つまで |

`sections`の見出しはClaudeが決める。待っていること、決まったこと、知っておいてほしい前提、最近片付いたものなど、セッションによって要る節が違うからだ。コードを書くセッションと、複数の作業者を見ているセッションでは、並べたいものが違う。

Modが節ごとに縦に並べて、paneの幅で折り返す。Markdownの表はpaneの幅に合わせて描かれないので使わない。

## いつ書き直すか

節目だけにするよう、ツールの説明と、ONのセッションに渡す説明（`hooks/context.ts`の`SESSION_CONTEXT`）で頼んでいる。

- 取り組む作業が切り替わったとき
- まとまった作業が片付いたとき（頼まれたコミット、PRのマージ、レビューの1巡）
- 利用者に決めてほしいことが増えたか、片付いたとき

Claudeが節目を見落としたときのために、最後に書いてから5ターンたつと、Modが「古くなっていたら書き直して」という文を送る。Claudeは、変わっていれば書き直し、変わっていなければ一言で終える。

| 条件 | 動き |
|---|---|
| 数えるターン | メインのターン。サブエージェントのターン、書き直したターン、催促で始まったターンは数えない |
| 催促する時点 | 5ターンめが、答えて終わったとき。中断やエラーで終わったら、次に答えて終わったターンまで待つ |
| 催促の後 | 数え直す。書き直されなくても、次の催促は5ターン後 |

催促は、次のプロンプトに文を足す形でなく、Modがターンを始める形にした。利用者が離れているあいだに書き直させるためだ。催促のターンは、利用者の画面に「devrepが送った」と分かる形で出る。

paneの上には「どれだけ前に書いたか」と「書いた後に終わったターンの数」が、`3時間前に更新 +2`の形で出る。書いた日時は、「いま」の見出しの横に出る。すぐに直したいときは「更新を頼む」（`u`）を押す。

小さいモデルにターンごとに書かせる形は取らなかった。会話の末尾しか読ませられないので、全体の順が不正確になる（2026-10-10に利用者と決めた）。

## 開く、閉じる

| 操作 | 動き |
|---|---|
| Claudeが状況を書き直した | paneに出る。ターミナルが狭いと、モデルが開くpaneは置かれない |
| `/devrep` | フォーカスを移してpaneを開く。幅に関係なく出る |
| ONで状況が残っているセッションを開き直した | paneに出る |
| paneで`q` | 閉じる |

帯にボタンは無い。ボタンとpaneが別のModにあると、ターンの途中に押したときにターンが終わるまで開かないからだ（`docs/claude-code-mods.md`の「操作」）。

## 覚えているもの

ONかどうか、状況、催促までのターンの数を、`$.store`にセッションごとに持つ（キーは`session:<セッションID>`）。セッションを開き直しても残る。覚えておくのは30セッションまでで、最後に書いた順に古いものから消える。

## 開発

```bash
claude plugin validate mods/devrep
claude plugin test mods/devrep
```
