# devrep

作業の状況をpaneに置いておくMod。しばらく離れていたセッションに戻ったとき、会話を読み返さずに、いま何をしていて、次に何をするか、自分が何をすれば作業が進むかが分かる。

状況は、会話を分岐させて書かせる（`$.model.fork`）。メインのClaudeには何も送らず、メインのターンも使わない。

```
[閉じる] [更新する] [自動更新をOFFにする]
3時間前に更新 +2

あなたがすること
□  /reload-plugins を打つ
□  Q3 に答える

いま（2026-10-10 23:05）
帯の幅の計算を直している

次にすること
1. テストを足す
2. READMEに反映する

決まったこと
-  表は使わない
```

## 書く時点

| 操作 | 動き |
|---|---|
| paneの「更新する」（`u`） | その場で書く。自動更新がOFFでも書ける |
| 自動更新がON | 最後に書いてから5ターンたつと書く |
| 自動更新をONにする（paneの`o`、`/devrep on`） | ONにして、その場で書く |
| 自動更新をOFFにする（paneの`o`、`/devrep off`） | 自動では書かなくなる。書いてある状況は残る |

既定はOFFで、セッションごとに切り替える。

自動更新の決まりは次のとおり。

| 条件 | 動き |
|---|---|
| 数えるターン | メインのターン。サブエージェントのターンは数えない |
| 書く時点 | 5ターンめが、答えて終わったとき。中断やエラーで終わったら、次に答えて終わったターンまで待つ |
| 書けなかったとき | 知らせない。次に答えて終わったターンで書き直す |

「更新する」で書けなかったときは、理由をtoastで知らせる。書いているあいだは、paneに「書いています…」と出し、もう一度押しても重ねて書かない。

## 書かせ方

ターンが終わったときに、会話を分岐させてメインのモデルに1回だけ答えさせ、JSONで状況を返させる。依頼の文は`hooks/prompt.ts`の`forkPrompt`にある。

- 分岐が読む会話は、メインが最後に送った要求までで、その返事である直前の答えは入っていない。そこで、答えて終わったターンの答えを依頼の文に入れる。次のターンが始まったら、その答えは捨てる
- 前に書いた状況も入れる。片付いたものや、利用者が済ませた`todo`を、前と比べて直させる
- 返事は会話に残らない

メインに書かせる形をやめたのは、書き直しの催促が1ターンを使い、変わっていなくても「変更なし」と答えさせることになるからだ。書き方の説明もメインの文脈に積まれていた（2026-10-29に利用者と決めた）。サブエージェント（`$.agent.spawn`）は立てない。状況は会話から書けるのでツールが要らず、タスクの一覧にエージェントを増やすことになる。

小さいモデルに書かせる形も取らなかった。会話の末尾しか読ませられないので、全体の順が不正確になる（2026-10-10に利用者と決めた）。分岐はモデルを選べないかわりに、メインの要求のキャッシュを使う。

## 状況の中身

| 項目 | 中身 |
|---|---|
| `now` | いましていること。必須 |
| `next` | 次にすること。取りかかる順に1〜6個。必須 |
| `todo` | 利用者が自分でしないと作業が進まないこと。実行してほしいコマンド、画面やブラウザで確かめてほしいこと、決めてほしいこと。急ぐ順に6個まで。無ければ空 |
| `sections` | そのほかの節。見出しと項目（1〜6個）の組を、6つまで |

`todo`は、paneのいちばん上に「あなたがすること」として出す。戻ってきた利用者が最初に知りたいのは、自分が何をすれば作業が進むかだからだ。件数はプロンプトの下の`devrep`の札にも出るので、paneを閉じていても気づける。`questions`の保留は「Q3に答える」と番号で書かせ、中身を繰り返させない。

`sections`の見出しは分岐したモデルが決める。決まったこと、知っておいてほしい前提、最近片付いたものなど、セッションによって要る節が違うからだ。

Modが節ごとに縦に並べて、paneの幅で折り返す。Markdownの表はpaneの幅に合わせて描かれないので使わない。

paneの上には「どれだけ前に書いたか」と「書いた後に終わったターンの数」が、`3時間前に更新 +2`の形で出る。書いた日時は、「いま」の見出しの横に出る。

## 開く、閉じる

| 操作 | 動き |
|---|---|
| プロンプトの下の行の`devrep`の札 | フォーカスを移してpaneを開く。幅に関係なく出る。Claudeが作業している最中でもすぐ開く。自動更新がONか、状況が書かれているセッションでだけ出る。`todo`があれば、札の右にその件数が出る |
| `/devrep` | フォーカスを移してpaneを開く。幅に関係なく出る。ターンの途中に打つと、ターンが終わってから開く |
| 自動更新がONで状況が残っているセッションを開き直した | paneに出る |
| paneで`q` | 閉じる |

自動で書き直したときは、paneを開かない。利用者が閉じたpaneを、5ターンごとに開き直さないためだ。

札は、このModが自分でプロンプトの下の行に足している。下の層（エンジンの元の表示、`status-band`の帯、ほかのModの札）が描いたものを受け取り、その右に札を1つ足して返す。札とpaneが同じModにあるので、コマンドを通さずに直接開ける。別のModのボタンからコマンドで開くと、ターンの途中に押したときにターンが終わるまで開かない（`docs/claude-code-mods.md`の「操作」）。

札を右端に出すには、`settings.json`の`enabledPlugins`で、`devrep@dotclaude`を`status-band@dotclaude`より前に書く。並び順の決め方は`mods/README.md`にある。

## 覚えているもの

自動更新がONかどうか、状況、書いてから終わったターンの数を、`$.store`にセッションごとに持つ（キーは`session:<セッションID>`）。セッションを開き直しても残る。覚えておくのは30セッションまでで、最後に書いた順に古いものから消える。

## 開発

```bash
claude plugin validate mods/devrep
claude plugin test mods/devrep
```
