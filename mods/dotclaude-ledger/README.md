# dotclaude-ledger

dotclaudeの作業コピーへの書き込みを、どのセッションが何のために書いたかとともに記録するMod。

## なぜ要るか

`~/.claude`の`docs`、`skills`、`rules`などはdotclaudeへのリンクで、どのプロジェクトのセッションも同じ作業コピーを直接書く（retroの書き手、`/re`、手で頼んだ直し）。コミットするのはdotclaudeで開いたセッションだけにしている。各セッションがコミットすると、ほかのセッションの書きかけを巻き込み、案件の文脈で書いた名前を、書いた本人が見落としたまま公開するためだ。

まとめてコミットする側は、差分だけでは、どの変更がどのセッションの何の依頼で入ったかが分からない。このModがそれを記録し、`dotclaude-sync`のスキルが読む。

## すること

- `Edit`と`Write`が成功した後、書いたファイルの実体のパスがdotclaudeの中（`workspace/`、`.jj/`、`.git/`の下を除く）なら、`~/.claude/dotclaude-ledger/<セッションID>.jsonl`に1行足す
  - 記録するのは、時刻、ツール、セッションID、サブエージェントのID、セッションの作業ディレクトリ、リポジトリの中のパス、書いた中身の頭（300文字）、書いた理由に当たる依頼の文（600文字）
  - 依頼の文は、メインのセッションなら利用者の最後の発言、サブエージェントならそのエージェントへの最初の依頼
- 全セッションの記録にある、未コミットのファイルの数を、プロンプトの下の行の右に`dotclaude N`と出す。セッションの開始時、書き込みの後、ターンの終わりに読み直す
- セッションの始めに、ほかのプロジェクトのセッションではdotclaudeをコミットしないことをClaudeに伝える

dotclaudeのリポジトリの場所は、`~/.claude/CLAUDE.md`のリンク先から読む。リンクが無いマシンでは何も記録しない。

## 記録の扱い

記録はリポジトリの外にあり、公開されない。ただし、元のプロジェクトのパスと依頼の文が入るので、`dotclaude-sync`は、その文をコミットメッセージに書き写さない。

push した後、`bun ~/.claude/skills/dotclaude-sync/sync.ts push`が、作業コピーに残っていないファイルの記録を消す。記録の形は`hooks/ledger.ts`にあり、スクリプトも同じ関数で読む。

## 拾わないもの

Bashで書いた変更（`sed -i`、リダイレクト）は記録しない。`dotclaude-sync`では「記録なし」と出て、差分だけで判断する。
