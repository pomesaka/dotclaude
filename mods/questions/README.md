# questions

Claudeが利用者に確かめずに仮に決めて先へ進んだことを、あとで決めるための一覧を出すMod。保留は、決める前に、会話を引き継いだ別のエージェントと相談できる。

一覧に1件以上あると、プロンプトの下の行の右に`pending N`の札が出る。`N`は残っている件数。押すと一覧のpaneが開く。コマンドを通さずに直接開くので、Claudeが作業している最中でもすぐ出る。

## 読み込み

マーケットプレイス`dotclaude`から入れる。手順は`mods/README.md`にある。

## プロンプトの下の行

この行は、複数のModが重ねて描く。`questions`は、下の層（エンジンの元の表示、`status-band`の帯、ほかのModの札）が描いたものを受け取り、その右に札を1つ足して返す。ほかのModの中身は知らない。

**`settings.json`の`enabledPlugins`で、`questions@dotclaude`を`status-band@dotclaude`より前に書く。** 先に書いたModが外側になり、札が右に並ぶ。`claude plugin install`は末尾に足すので、入れた後に行を移す。後ろにあると、札が帯の右でなく、帯の下の行に出る。包み方の決まりは`mods/refs/README.md`に書いてある。

## 保留の一覧

Claudeが利用者に確かめずに仮に決めて先へ進んだことを、あとで決めるための一覧。`pending`を押すと出る。

Claudeは`add_question`で、決めること（`question`）、説明（`detail`）、選択肢（`options`、2〜6個）、仮に置いた選択肢（`assumed`）を残す。残すと`Q3`のような番号が付く。保留を外しても、残りの番号は変わらず、外した番号を次の保留に付け直すこともない（付けた最大の番号を`qlast:<セッションID>`に覚えている）。同じ問いでもう一度呼ぶと、番号はそのままで中身が置き換わる。

```
q: 閉じる  選択肢を押すと、その答えがClaudeに届く

Q1 帯のボタンの名前                                     ×
保留が1件以上あるときに、帯の右に出る札の文字。
○ pending  いまの仮置き
○ todo
○ 保留
？ 詳しく聞く
✎ ほかの答えを書く
```

Claudeが保留を足すと、paneが自動で開く。フォーカスは移さない。ターミナルの幅が足りないと開かないが、プロンプトの下の行の`pending`の件数は増える。

どの問いも、説明と選択肢を開いたまま並べる。キーで行を選ぶ操作は無く、クリックで答える。

| 操作 | 動き |
|---|---|
| 選択肢を押す | その1件の答えが、すぐClaudeに届く。選んだ選択肢に`●`が付き、行の右に「送信済」と出る。押し直すと、新しい答えをもう一度送る |
| `？ 詳しく聞く` | その保留の相談を、別のpaneで始める（次の節）。答えの印は付かない |
| `✎ ほかの答えを書く` | 入力欄に「Q1（帯のボタンの名前）は、」を入れて、paneを閉じる。続きに答えを書いて送る |
| `×` | 答えずに一覧から外す |
| `q` | 閉じる |

答えは「【保留への回答】Q1 帯のボタンの名前: todo」の形で届く。仮置きと同じ選択肢なら、末尾に「（仮置きのまま）」が付く。Claudeは決定を反映してから、`resolve_question`でその番号を外す。外れるまでは、選んだ印を付けたまま一覧に残る。

保存はセッションごと（`$.store`の`qs:<セッションID>`）。開き直したセッションでも残る。

## 保留の相談

「詳しく聞く」を押すと、メインの会話を引き継いだ別のエージェント（フォーク）が立ち、最初の説明を始める。メインが動いている最中でも始められ、やりとりはメインの会話に残らない。

会話は、エンジンのエージェントの会話の画面でする。通常のセッションと同じ表示で、入力欄に書いた文がそのエージェントに届く。richの`show`のような道具も、会話の行に描かれる。

| 開き方 | 使える場面 |
|---|---|
| 画面の下の並びで、下矢印で`fork Q1 の相談`を選んでEnter | エージェントが答えている最中。並びが出ている |
| 相談のpaneの「一覧を開く（/tasks）」を押して、Enter | 答え終わって、並びから消えた後 |

メインへは、画面の下の並びで`main`を選ぶと戻れる。メインは、相談のあいだも裏で動き続ける。

相談のpaneは、会話の横に出しておくもので、保留の問いと説明、会話の開き方、結論を送るボタンを置く。

```
閉じる  読むだけの相談。メインの会話には残らない
Q1 帯のボタンの名前
保留が1件以上あるときに、帯の右に出る札の文字。

会話は「Q1 の相談」の画面でします。画面の下の並びで、下矢印で選んでEnterを押すと開きます
▸ 並びに出ていなければ、一覧を開く（/tasks）

決めたら、押してメインへ送る
○ pending  いまの仮置き
○ todo
○ 保留
✎ 選択肢に無い結論を送る
```

| 操作 | 動き |
|---|---|
| 選択肢を押す | その答えをメインのClaudeへ送り、相談を閉じる。保留の一覧に`●`が付く |
| `✎ 選択肢に無い結論を送る` | 相談の要約だけをメインへ送り、相談を閉じる |
| `▸ 一覧を開く（/tasks）` | エージェントの一覧を開く。スラッシュコマンドなので、メインの会話に1行残る |
| `閉じる` | paneを閉じる。相談は残り、同じ保留の「詳しく聞く」で開き直す |

メインへ届く文は次のとおり。

- 相談で何も聞かずに選択肢を押した: 保留のpaneで選んだときと同じ「【保留への回答】Q1 帯のボタンの名前: todo」
- 相談で聞いた後に選択肢を押した: その後ろに「相談で決まったこと: …」の行が付く。エージェントに頼んだ2〜3文の要約で、相談の中で付いた条件を渡す。30秒待って要約が来なければ、付けずに送る
- 選択肢に無い結論: 「Q1（帯のボタンの名前）について相談した結論: …」

会話の中にエージェントが描いた質問のボタン（richの`show`の質問など）でも、結論を送れる。保留の選択肢と同じ綴りの選択肢を押すと、paneで選択肢を押したのと同じ扱いになる。仕組みは次のとおり。

- ほかのModのボタンが押されたら、そのボタンの行（ツールの呼び出し）が、相談用のエージェントの会話にあるかを調べる
- あれば、押された時刻を覚える。ボタンの動きは止めない
- 5秒以内にそのModがメインへ送ろうとした文から、保留の選択肢を読み取れたら、その文は止めて、結論として送り直す。読み取れなければ、そのまま通す

読み取るのは「問い: 選択肢」の形の行で、richの答えの文に合わせてある。

エージェントが答えている最中は、結論を送れない。要約がその答えに混ざるからだ。

相談の会話は、エージェントが答え終わった後、その会話の画面を開いていないと30秒ほどで一覧から消える。エンジンの決まった動きで、Modからは延ばせない。メインで作業を続ける前に、相談を終えて結論を送る。消えた後に、同じ保留の「詳しく聞く」をもう一度押すと、新しいエージェントを立て直す。前のやりとりは引き継がれない。

最初の説明の頼み方は、環境変数`QLIST_EXPLAIN_PROMPT`で差し替えられる。既定は「詳しく説明して」。`/explain-inline で説明して`と書けば、エージェントは`explain`のスキルの手順で、会話の中に描く。 説明の順番と、読み手の前提の見積もり方は、そのスキルが決めている。

### 相談用のエージェントが使えるツール

ファイルを書き換えないように絞ってある。

- `Read`と、読むコマンドだけでできたBash（`rg`、`fd`、`ls`、`cat`、`head`、`tail`、`wc`、`jq`、`jj log`、`jj diff`、`jj show`、`jj status`、`jj file show`、`jj file list`）。`&&`や`|`でつないだ文は、分けた全部がこの一覧に入っているときだけ通す。リダイレクト、`$(…)`、バッククォート、別のコマンドを実行させるフラグ（`fd -x`、`rg --pre`）があれば拒む。そのうえで、エンジンの権限の判定が「確認なしで通す」のものだけを実行させる
- MCPのツール、スキル（`Skill`）、ツールの読み込み（`ToolSearch`）。説明にrichの`show`などを使えるようにするためだ。書き込むMCPのツールもここでは見分けず、エンジンのふだんの権限の判定に任せる
- ほかのツール（`Write`、`Edit`、エージェント）はすべて拒む

絞り込みは、このModの`tool.call`と`tool.check`のhookで掛けている。エージェントを立てる処理を、ボタンの`onPress`でなく`ui.press`のhookに置いているのは、`onPress`の中から立てたエージェントには、このModのhookが呼ばれないからだ。

相談用のエージェントかどうかは、エージェントの一覧の説明（`Q1 の相談`）で判定する。Modが覚えているIDは、セッションを裏に回して戻すと消えるためだ。開いている相談（保留とエージェントのID）も、`$.store`の`consult:<セッションID>`に覚えている。

エージェントが答え終わると、メインに終了の知らせが届く。Modがこの知らせを捨てるので、メインは動かない。会話の行には「Prompt dropped by a hook: 相談用のエージェントの終了の知らせ（メインには渡さない）」が1行出る。

相談は一度に1つで、別の保留の「詳しく聞く」を押すと、新しいエージェントで始め直す。

エージェントを立てられなかったときは、「Q1（帯のボタンの名前）について、詳しく説明して」をメインのClaudeに送る。「について、」より後ろは、同じ環境変数の頼み方になる。

## Claudeへの説明

セッションの始めに、`hooks/context.ts`の`SESSION_CONTEXT`をClaudeへ渡す。保留を残すとき、答えが届く文の形、相談の結論が届く文の形、外すときを書いてある。起動、再開、fork、`/clear`、compactのたびに渡す。サブエージェントには渡さない。

**仕様を変えたら、`SESSION_CONTEXT`も直す。**

## 開発

```bash
claude plugin validate mods/questions
claude plugin test mods/questions
```
