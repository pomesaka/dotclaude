# quiet-prompts

ほかのModが自分から送った文の行を、会話の中で1行に畳むMod。

Modが`$.prompt.submit`で文を送ると、エンジンは、送った文の全文に英語の枠を付けて、利用者の発言と同じ行として描く。devrepの催促なら、5ターンごとに5行ほどが会話に出る。利用者が知りたいのは、何が送られたかだけだ。

```
› Prompt from the devrep plugin
❯ devrep: 最後に作業の状況を書いてから5ターンたちました。古くなっていたら …
```

## 読み込み

マーケットプレイス`dotclaude`から入れる。手順は`mods/README.md`にある。

## 畳む行

| 行 | 畳むか |
|---|---|
| Modが自分から送った文（devrepの催促、prのマージやCIの失敗の知らせ） | 畳む。エンジンの枠を除き、最初の行を幅に収まるだけ出す |
| Modがエージェントに宛てた依頼文（`[名前: …]`で始まる。保留の相談用に分岐した会話の最初の行、next-stepの問い合わせ） | 畳む |
| 利用者の操作でModが送った文（next-stepの札、questionsの回答） | 畳まない。何を送ったかの記録になる |
| 利用者が打った文 | 畳まない |

`ctrl+o`で開いた表示では、どの行も畳まない。全文を読める。

描き直すのは画面の行だけ。保存される文と、モデルが読む文は変わらない。

## できないこと

- **行の上の「Prompt from the … plugin」の見出しは消せない。** エンジンが部品の外で描いている。`asUser`で送った文にも付く
- **このModが送る文は無い。** あっても、自分の行は描き直せない（下の節）

## なぜ別のModなのか

Modは、自分が送った文の行を描き直せない。その行には自分のhookが呼ばれず、ほかのModのhookなら効く。v2.1.296の実機で、送るModと描き直すModを分けて確かめた。devrepの中に書いても効かないので、畳む役をここに置いている。

依頼文を`[名前: …]`で始める決まりは、questionsとnext-stepが使っている。新しいModがエージェントに依頼文を送るときも、この形で始めれば畳まれる。

## 開発

```bash
claude plugin validate mods/quiet-prompts
claude plugin test mods/quiet-prompts
```
