# next-step

ターンが終わった後に、利用者が次に打ちそうな文をプロンプトの上に札として並べるMod。札を押すと、その文がClaudeに届く。プロンプトを打たずに、押すだけで作業を進められる。

```
╭──────────────────────╮ ╭──────────────────────╮ ╭──────────────────────╮
│ 1: コミットして      │ │ 2: テストを足して    │ │ 3: READMEにも反映し  │
│                      │ │                      │ │ て                   │
╰──────────────────────╯ ╰──────────────────────╯ ╰──────────────────────╯
札を押すと、その文がClaudeに届く  × 消す
```

## 仕組み

Claude Codeは、ターンが終わると「利用者が次に打ちそうな文」を1つ当てて、入力欄に薄く出す（prompt suggestion。Tabで取れる）。Modは、その案が出たことを`prompt.suggest`のhookで受けて、次の2つをする。

1. その案を、先頭の札にする。入力欄の薄い表示はそのまま残す
2. `$.model.fork`で会話を分岐させ、同じモデルに「ほかに打ちそうな文」を3つまで聞いて、残りの札にする

| 時点 | 動き |
|---|---|
| ターンが答えて終わった | 直前の答えを覚える。札はまだ出さない |
| Claude Codeの案が来た | 先頭の札を出し、「ほかの案を考えています…」と添える。分岐して聞きはじめる |
| 分岐の返事が来た | 札が増える。返事が無い、読めない、先頭と同じ案だけ、のときは先頭の1枚のまま |
| 札を押した | その文を、利用者が打って送ったのと同じ形で送る。札は消える |
| `× 消す`を押した | 送らずに札を消す。遅れて来た返事も捨てる |
| 次のターンが始まった | 札を消す。自分で打って送ったときも同じ。遅れて来た返事は捨てる |

Claude Codeが案を出さなかったターンには、札も出さない。Claude Codeは、次の一手がはっきりしないターンや、エラーや行き違いの後には黙るよう指示されている。そういうターンに札を並べても外れやすい（2026-10-10に利用者が決めた）。中断やエラーで終わったターン、サブエージェントのターン、ほかのModが出した案でも、札は出さない。

ターンの途中と、調査（survey）が帯を使っているあいだは、札を描かない。

帯にフォーカスを移すと（`ctrl+x tab`かクリック）、札の番号のキーでも選べる。入力欄にいるあいだは、番号のキーは効かない。

## 「当てる」と頼む

分岐して聞くときの文（`hooks/suggestions.ts`の`forkPrompt`）は、「利用者が次に打ちそうな文を当てる」と頼んでいる。「次に送るとよい指示を提案して」とは頼まない。

最初の版は後者で、小さいモデル（haiku）に会話の末尾だけを渡していた。それらしい案は並ぶが、的を射たものが出なかった。Claude Code自身の案は当たるので、実行ファイルから指示文と呼び出し方を読んで比べると、違いは2つあった。

| | Claude Codeの案 | next-stepの最初の版 |
|---|---|---|
| 読ませる会話 | 全部。メインの会話を分岐させる | 末尾の6発言と直前の答え |
| 頼み方 | 利用者が打とうとしている文を当てる。新しい案は出さない | 次に送るとよい指示を提案する。向きの違う案を混ぜる |

いまの版は、どちらもClaude Codeの側に合わせている。

## 費用と速さ

Claude Codeが案を出したターンごとに、メインのモデルの呼び出しが1回増える。分岐は、メインが最後に送った要求（モデル、システムプロンプト、会話）をそのまま送り直すので、APIのキャッシュが効く。会話の全部を読ませても、小さいモデルにキャッシュなしで読ませるより速い。モデルは選べない（キャッシュがモデルごとなので）。

依頼と返事は会話に残らないので、コンテキストは増えない。

## Claudeへの説明

分岐した問い合わせは会話に残らないので、メインのClaudeには、どんな札が出ているかが見えない。セッションの始めに、次のことを渡す（`hooks/context.ts`の`SESSION_CONTEXT`）。

- 札から届く文は、利用者ではなくモデルが書いたものだ。言い回しがリポジトリの決まりと違っていても、意図をくんで決まりどおりに進める。pushや削除のように確認が要る操作は、確かめてから進める
- 問いで終わる答えには、その問いへの答えが札になる。答えの末尾に、次の一手の選択肢を並べなくてよい

## 覚えているもの

札は`$.state`の`next-step.suggestions`に持つ。セッションを開き直すと消える。案は直前の答えに対するものなので、開き直した後まで残さない。

## 開発

```bash
claude plugin validate mods/next-step
claude plugin test mods/next-step
```
