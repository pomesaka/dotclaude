# next-step

ターンが終わるたびに、次に頼みそうなことをプロンプトの上に札として並べるMod。札を押すと、その指示がClaudeに届く。プロンプトを打たずに、押すだけで作業を進められる。

```
╭──────────────────────╮ ╭──────────────────────╮ ╭──────────────────────╮
│ 1: テストを足す      │ │ 2: コミット          │ │ 3: READMEを直す      │
│ 境界のケースをtable  │ │ ここまでをコミットし │ │ 保留の一覧の節に、番 │
│ drivenで足して       │ │ て                   │ │ 号の付け方を書いて   │
╰──────────────────────╯ ╰──────────────────────╯ ╰──────────────────────╯
札を押すと、その指示がClaudeに届く  × 消す
```

## 仕組み

ターンが終わると、Modが`$.model.complete`で、小さいモデルに「利用者が次に送るとよい指示」を聞く。先頭の1個は直前の答えの素直な続き、残りは向きの違う案（やり残しの確認、別の進め方、一歩先の作業、見直し）にするよう頼んでいる。渡すのは、`$.session.messages()`で読んだ会話の末尾6件と、直前の答えだけだ。返事はJSONで、札の言葉（`label`）と、押したときに送る文（`prompt`）の組が0〜4個入っている。

聞くモデルは、環境変数`NEXT_STEP_MODEL`で変えられる。無ければ`haiku`を使う。書けるのは、`--model`に渡せる別名かモデルのID。

| 時点 | 動き |
|---|---|
| ターンが終わった | モデルに聞く。返事を待つあいだは「次の一手を考えています…」と出す |
| 返事が来た | プロンプトの上に札が並ぶ。先頭の札（直前の答えの続き）に色が付く |
| 札を押した | `prompt`の文を、利用者が打って送ったのと同じ形で送る。札は消える |
| `× 消す`を押した | 送らずに札を消す |
| 次のターンが始まった | 札を消す。自分で打って送ったときも同じ。遅れて来た返事は捨てる |

答えが利用者への問いで終わっていれば、その問いへの答え（「直して」「そのままで」など）が先頭から並ぶ。案が無いとモデルが答えたターンと、返事を読めなかったターンでは、何も出さない。

モデルに聞くのは、メインのセッションが答えて終わったターンだけだ。中断やエラーで終わったターン、サブエージェントのターンでは聞かない。ターンの途中と、調査（survey）が帯を使っているあいだは、札を出さない。

送る文は、30文字くらいまでの一言にするよう頼んでいる。Claudeは会話を覚えているので、経緯や対象の説明は書かせない。札では、折り返して全文を出す。何が送られるかを読んでから押せるようにするためで、長い文があると帯はそのぶん高くなる。

帯にフォーカスを移すと（`ctrl+x tab`かクリック）、札の番号のキーでも選べる。入力欄にいるあいだは、番号のキーは効かない。

## 費用

ターンごとに、モデルの呼び出しが1回増える。読ませるのは会話の末尾（1件あたり1,500文字まで）と直前の答え（6,000文字まで）で、返事は800トークンまでに抑えている。15秒で返事が来なければ、そのターンの札は出さない。依頼と返事は会話に残らないので、コンテキストは増えない。

## 案の質の限界

聞く先のモデルは、会話の一部しか読んでいない。CLAUDE.mdもスキルも知らないので、送る文は一般的な言い方になる（このリポジトリの決まりが`/jjcommit`でも、札は「コミットして」と書く）。受け取る側のClaudeは決まりを知っているので、意図をくんで決まりどおりに進めるよう、セッションの始めに伝えてある。

会話の全文を踏まえた案が要るなら、`$.model.fork`を使う形にもできる。メインのモデルに全文を読ませるので、札が出るまでが遅い。最初はこの形で作り、遅さを理由にいまの形へ切り替えた。

## Claudeへの説明

問い合わせは会話に残らないので、メインのClaudeには、どんな札が出ているかが見えない。セッションの始めに、次のことを渡す（`hooks/context.ts`の`SESSION_CONTEXT`）。

- 札から届く指示は、利用者ではなく、会話の一部しか読んでいない小さいモデルが書いた文だ。言い回しがリポジトリの決まりと違っていても、意図をくんで決まりどおりに進める。pushや削除のように確認が要る操作は、確かめてから進める
- 問いで終わる答えには、その問いへの答えが札になる。答えの末尾に、次の一手の選択肢を並べなくてよい

## 覚えているもの

札は`$.state`の`next-step.suggestions`に持つ。セッションを開き直すと消える。案は直前の答えに対するものなので、開き直した後まで残さない。

## 開発

```bash
claude plugin validate mods/next-step
claude plugin test mods/next-step
```

モデルへの依頼の文は、`hooks/suggestions.ts`の`SYSTEM_PROMPT`（役割と返事の形）と`askPrompt`（会話の末尾と直前の答え）にある。
