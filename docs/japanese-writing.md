# 日本語の書き方

> **TL;DR**: 誰が何をどうしたかを1文で言い切る。比喩動詞、前置き、装飾記号を使わない。既存の文を直すときは意味を変えず、情報を足さない。

応答、ドキュメント、PR本文、コミットメッセージのどれを書くときも守る。出典は[nanaism/yomiyasu](https://github.com/nanaism/yomiyasu) v1.0.2（MIT）で、2026-10-02に`SKILL.md`と`references/`を読んでまとめた。元は書き終えた文章を直すスキルなので、書く時点で守る規則に組み替えてある。

## 文の組み立て

| 規則 | 避ける例 | 書く例 |
|---|---|---|
| 主語、対象、動作を1文に書く。「これ」「両者」「片方」は指す先が直前で分かるときだけ使う | 処理を流すたびに、状態が勝手に書き換わっていく | 処理を実行するたびに、意図せず状態が書き換わる |
| 道具や概念に意志を持たせない。働きを述べるだけの文はそのままでよい | このドキュメントがAPIの仕様を語っている | このドキュメントにAPIの仕様が書かれている |
| 比喩動詞をふだんの動詞に置き換える。「地味に」「〜てしまった」の含みは残す | この工夫が後々の運用で地味に効いてくる | この工夫をしておくと、後々の運用で目立たないながらも役立つ |
| 前置きで始めない。評価を言いたいなら述語に書く | 重要なのは、見た目ではなくデータ構造です | 見た目ではなく、データ構造が重要だ |
| 予告だけの文を書かず、中身の文に入る | 意識したい点があります。進捗共有が推奨されます | 定期的な進捗共有が役立つ |
| 「AではなくB」は、Aだと誤解されやすいときだけ使う | 目的は、単なる高速化ではなく安定稼働です | 目的は安定稼働だ |
| 接続詞と文頭の指示語は、前の文の何を受けるかを確かめて置く | 設定を変更しました。ただし、再起動が必要です | 設定を変更した後は、再起動が必要だ |
| 定型の結びを書かない | いかがでしたでしょうか。ぜひ試してみてください | 本文の最後の文で終える |

1段落には1つの話題だけを書く。「骨が折れる」「手を焼く」のような慣用句は使ってよい。迷ったら、AIが広まる前の人の文章でも見かける言い方かどうかで決める。

## リズムと装飾

| 項目 | 目安 |
|---|---|
| 文の長さ | 平均30〜45文字。60文字を超えたら2文に分ける。10文字未満の短文を続けない |
| 読点 | 1文に0〜2個。「前提を、」のような文頭の強調読点を打たない |
| 文末 | 同じ文末を3文続けない |
| 漢語 | 漢語が続いて硬くなったら、ひらがなや動詞に開く |
| 太字 | 1,000文字あたり1〜2箇所 |
| 箇条書き | 理由や因果の説明は地の文で書く。並列の項目、手順、比較は箇条書きや表でよい |
| 絵文字 | 使わない |
| コロン | 文末と見出しの直後に置かない |
| ダッシュ記号 | 使わない。助詞でつなぐ |
| カッコ | 情報が増えない言い換えのカッコを付けない |
| 和欧文間の半角空白 | 新しく書く文章では入れない。既存ファイルを編集するときはそのファイルに合わせる |

## 言い換える語

文字どおりの意味や技術用語として使うなら残す。比喩や飾りとして使っていたら言い換える。

| 避ける語 | 書き方 |
|---|---|
| 〜側に倒す | 〜を優先する、〜に統一する |
| 静かに壊れる、黙って無視される | 気づかないうちに使えなくなる、知らないうちに無視される。エラーや通知が出ないと分かっているときだけ「エラーを出さずに」と書く |
| 地味に効く | 目立たないが役に立つ |
| 時間を溶かす | 時間がかかってしまった |
| 1つずつ潰す | 1つずつ直す |
| 踏み込む、深掘りする | 詳しく調べる |
| 〜した瞬間 | 〜するとすぐに、〜した時点で |
| 正本 | 信頼できる唯一の情報源、マスターデータ |
| 〜を示唆している | 〜と考えられる、〜を表している |
| 落とし穴、事故、破綻、素通り | 見落としやすい点、思いがけない失敗、うまくいかなくなる、気づかず通る |
| 土台、入口、核心、線引き、構図 | 基本、手始め、いちばん大事な点、境界、全体の関係 |
| 手触り、肌感、温度感、熱量、泥臭い | 分かっている事実を書く |
| 解像度、腹落ち、メンタルモデル | 何をどこまで調べたかを書く |
| 本質的な、等身大の、地に足のついた | 削る。「本質」が文の主題なら残す |
| 真理、宿命、美学、深淵、極致 | 大げさな熟語を使わず、起きたことを書く |
| 意思決定OSのような造語 | 機能を説明する |

## 既存の文を直すとき

直す前に、元の文の主張、比重、言い切りの強さ、文の働きを確かめる。直した後もこの4点を同じに保つ。断定を推量に弱めたり、推量を断定に上げたりしない。評価の文を目標や予定の文に変えない。否定していたAを「Aに加えてB」と並べ直さない。

元の文と前後から分からない動作主、原因、条件、数値、例は足さない。ぼかした語を、より狭い具体的な事実に置き換えることもしない。情報が足りなくて具体的に書けないときは、本文で補わずに書き手へ確かめる。直す箇所がほとんどない文は書き換えない。
