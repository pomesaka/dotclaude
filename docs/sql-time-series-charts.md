# SQL 集計から時系列チャートを作るときの罠

- **`GROUP BY` は「値がある期間」しか返さない。チャートで 0 件の月/日を歯抜けにしないためにはアプリ層で期間を列挙してから 0 埋めする**: 月別・日別の受領件数などを棒グラフで出すとき、SQL 側の集計結果（`GROUP BY strftime(...)`）をそのまま横軸に使うと、受領 0 件の月はその月自体が結果セットから消える。棒グラフはそれで一見動いているように見える（棒が並ぶだけ）が、横軸のラベルが歯抜けになり「9 月の隣が実は 7 月だった」のような誤読を招く。対処: `[from, to]` の期間から月（または日）のリストをアプリ層で先に列挙し（`jstMonthsInRange` のような関数）、SQL の集計結果を `Map` に入れてから `months.map(m => byMonth.get(m) ?? zeroRow)` で埋める。判断基準: 「この集計を時系列チャートの横軸として使うか？」YES なら 0 埋めが要る。テーブル/リスト表示（値がある行だけ見せたい）なら不要。ある案件の宛先別内訳表がこの逆パターン（0 件の宛先はそもそも表示しない設計）。

- **表示する値が返金控除後の純額など「派生値」なら、並び替えも同じ派生値基準に統一する。サーバーの生値ソートをそのまま画面に渡すとズレる**: サーバー側 SQL は集計しやすい生値（返金控除前の総額）でソートしがちだが、画面は返金控除後の純額を表示する設計だと、生値順と純額順が食い違う行が出る（返金が多い行ほど順位が入れ替わる）。実機で画面を見て初めて「あれ、この順番おかしい」と気づく類のズレで、型チェックもテストも検出しない。対処: 画面側で「表示している値」を基準に並び替える関数（例: `byNetDesc`）を用意し、サーバーのソート順は無視する。
