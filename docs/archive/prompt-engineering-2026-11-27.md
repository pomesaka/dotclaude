# prompt-engineering.md から退避した項目（2026-11-27）

`docs/prompt-engineering.md`を原則にまとめたとき、文書から消えた元の文。各節の見出しの下に、残した原則と、元の項目の全文を置く。

## 1. repeated-phrasing

残した原則: 維持のしかた「望まない言い回しや質問が繰り返されるときは、禁止を足す前に、それを指示している文を探す」

- 同じ言い回しや質問が繰り返されるときは、禁止を足す前に、それを指示している文を探す。別の節に「〜と聞いてください」のような指示が残っていることが多い。見つけたら、その指示を消すか、行動の指示でなく状態の事実（「保存済みの事実はN件」）に書き換える。禁止を積み重ねると、文脈が膨らみ、ほかの指示が埋もれる

## 2. tools-listed-as-alternatives

残した原則: 指示の書き方「道具を『使い分け』として並べると、1回に1つだけ呼ぶものと読まれる」

- 道具を「使い分け」として並べると、1回に1つだけ呼ぶものと読まれる。一緒に呼んでよい道具は、そのことを文で書き、両方を呼ぶ例を1件添える。「いつも呼ぶもの」「条件つきで加えるもの」の順に並べる

## 3. reference-vs-usage

残した原則: どこに置き、いつ読ませるか「置き場は、その文を読むべき人が、どの作業のときにどの文書を開くかで決める」

- 道具の説明、どの使い方にも当てはまる書き方、特定の用途だけの決まりは、読む人ごとに置き場を分ける。道具のリファレンスに用途の書き方の勧めが混ざると、どの使い方をする人にもその書き方が押しつけられる。リファレンスには何が書けて、どう動くかだけを置き、どの使い方にも当てはまる書き方はその道具を使うスキルに、用途だけの決まりはその用途のスキルに置く。用途のスキルにだけ置くと、その用途でない作業では誰も読まない。判断基準は「この文を読むべき人は、どの作業のときにどの文書を開くか」

## 4. maintenance-bullets

残した原則: 「どこに置き、いつ読ませるか」の表と、「指示の書き方」の「強さを語で表さない」、`agent-environment.md`の守られない行の直し方

- 足すのは、同じ間違いが2回起きたとき、レビューで「知っているべきだった」ことが見つかったとき、前の会話と同じ訂正を打ったとき
- 手順になってきた項目はスキルへ、コードの一部でだけ要る項目は`rules/`へ移す
- 絶対の形で書かれた規則は、範囲と理由つきに書き直すか、hookにする
