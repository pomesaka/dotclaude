# Edit Tool Tips

> **TL;DR**: `old_string` は Read の出力からそのままコピーする（手で書くと細かい違いで一致しない）。Edit が失敗したら、同じターンのうちに Read して Edit し直すところまで終える（失敗したまま進むと、直したつもりになる）。

Edit ツール（`old_string` → `new_string` の完全一致置換）で詰まりやすい点の一覧。

## `old_string` は Read の出力から byte-for-byte でコピーする — 手書きすると微差でマッチ失敗する

Edit の `old_string` は「見た目の一致」ではなく「バイト列の完全一致」を要求する。人間の目には同じに見えるが Unicode コードポイントが異なる文字がファイル中にあると、手書きした `old_string` が silent にマッチ失敗する（Edit ツールはエラーを返すが、原因が「見えない差分」だと診断に時間がかかる）。

主な誤マッチ源は次のとおり。

- **全角 `（）` vs 半角 `()`**: 日本語コンテキストのコメント・issue 本文・PR ボディで混在しやすい。全角 U+FF08/U+FF09 と半角 U+0028/U+0029 は別文字。
- **全角スペース `　`（U+3000） vs 半角スペース `  `（U+0020）**: 日本語文脈のインデントで混入する。
- **NO-BREAK SPACE（U+00A0） vs 通常スペース**: コピペ元がリッチテキスト（Notion・Slack・ブラウザ）だと入りやすい。
- **ダッシュ類**: `-`（HYPHEN-MINUS U+002D）/ `—`（EM DASH U+2014）/ `–`（EN DASH U+2013）/ `ー`（KATAKANA-HIRAGANA PROLONGED SOUND MARK U+30FC）。
- **引用符**: `"`（U+0022） vs `"`（U+201C）/`"`（U+201D）/`「」`（U+300C/U+300D）。
- **行末の trailing space**: 目視では見えないが `old_string` に含めないとマッチしない（逆に手書きで足しても含まれていない）。

### 対処

1. **必ず Read の出力を直接コピーする**。「記憶で書く」「rg grep 結果から書く」「PR ボディから書く」のいずれも危険（周辺文字が微妙に違う可能性がある）。
2. マッチ失敗したら、`old_string` と Read 出力を同じ視覚範囲で並べて目視 diff せず、まず `rg -n "<マッチさせたい部分の中央 5〜10 文字>" <file>` で当該行を Read から再取得し、その行を丸ごとコピーし直す。「見た目一致してるはずなのになぜ」で 5 分費やすより「Read で取り直す」が最短。
3. 日本語混じりのコードコメントや issue Markdown を編集するときは、括弧・スペース・ダッシュを含む範囲を `old_string` に選ばない（誤マッチリスクの高い文字を避けて、ASCII 純度の高いアンカーを選ぶ）。

### 実例

- ある案件の issue（PR #256）: issue ファイルの `## 受け入れ基準（詳細）` を Edit しようとしたが、`old_string` に半角 `(` で「受け入れ基準(詳細)」と書いたためマッチ失敗。実ファイルは全角 `（` `）` だった。Read の出力から丸ごとコピーで解決。

## Edit が失敗したら同ターンで Read → 再 Edit まで完了させる — 失敗したまま次に進むと「修正済み」と誤認する

Edit がエラー（マッチ失敗・"File has not been read yet" 等）を返した後、別の修正に移ってから戻ってくるつもりで忘れると、修正が適用されていないのに頭の中では「対応済み」として扱われる。自己申告ベースの確認（「Round 1 で直した」）では検出できず、ゼロベースの再レビュー・他者の指摘で初めて発覚する（発覚しなければそのまま残る）。

### 対処

1. 失敗した Edit はその場で Read → 再 Edit を完了させる。「後でまとめて」に回さない。
2. 複数修正をバッチ適用したときは、終了時に `rg "<修正後の文字列>" <file>`（または `rg "<消したはずの文字列>"` がゼロ件）で全修正の着地を機械的に確認する。適用の記憶ではなくファイルの現状を証拠にする。

### 実例

- ある案件の PR: `invoice-summary-panel.tsx` の stale JSDoc（`LineItemMatchTable` → `MatchTable`）を Round 1 で修正したつもりが Edit 失敗後の再適用漏れで残存し、Round 2 のゼロベースレビューで同一指摘が再検出された。
