# フロントエンド実装の規約

> **TL;DR**: 画面に何を出し、何を出さないかの決めごと（完了の画面の行き先、補足の文、成功の知らせ、外部のシステムのキー）と、印刷と画像の読み込みでのブラウザの癖をまとめてある。

この文書は、画面を作る、直すときに読む。整理する前の版は`archive/2026-11-16/docs/frontend-policy.md`にある。

## 画面に出すもの

- **完了や成功で終わる画面に、次の行き先を出す**。エラーには誰でも導線を付けるが、完了の画面は文だけで終わりやすく、レビューでも正しく完了しているようにしか見えない。文を1行足すのでなく、実在する行き先（ダッシュボード、一覧、元の導線）を出す。行き先が無いなら「閉じて大丈夫」と書いて終える。権限や認証の都合で行き先を出せないなら、その理由をコードのコメントに残す。判断基準は「この画面を最後まで正しく使い終えた人は、この後どこへ行くのか」。
- **画面に補足の文、キャッチコピー、副ラベルを足さない。それが無いと意味が通らない画面は、レイアウトを直す**。補足の文は、並び、まとまり、見出し、状態の見せ方で伝わっていない意味を、言葉で埋めたものだ。足すほど操作と値が文字に埋もれ、利用者は補足を読まなくなる。エラーの文と、取り消せない操作の確認文は、レイアウトでは代わりにならないので残す。判断基準は「この文を消したら、利用者は何を間違えるか。それはレイアウトで防げないか」。
- **成功した操作の結果は、画面を見て分からないものだけ知らせる。失敗と、続きの作業があることは、いつも知らせる**。一覧に行が増えたのに「登録しました」も出すと、同じことを2回伝え、読んでほしい知らせが埋もれる。画面に出ない結果（外部へのメールの送信、一覧に出ない子の追加）は、知らせないと利用者が開き直して確かめることになる。知らせは、モーダルの中の1行でなく、モーダルを閉じた元の画面の上端に、閉じるボタンつきのバナーで出す。成功と「運営が手で続きをする必要がある」は色で分け、成功は緑系にする。判断基準は「このバナーを消したら、利用者はこの結果を画面のどこで確かめられるか」。
- **外部のシステムの内部のキー（Stripeの`requirements.currently_due`にある`representative.address_kana.city`など）を利用者に見せず、自前の和訳の表も持たない**。キーの羅列は利用者にはエラーの列に見える。対応表を持つと、相手が要件を足したときに知らないキーが抜け落ち、それを自分のテストでは検出できない。件数や有無のような、相手の語彙に依存しない要約だけを出し、詳細は相手の画面に任せる。判断基準は「この文字列の語彙を決めているのは誰か」。

## ブラウザの癖

- **ブラウザの印刷で用紙の大きさや余白まで決めたいなら、対象のブラウザの印刷プレビューで確かめてから約束する**。`@page { size; margin }`はブラウザごとに効き方が違う。macOSのSafariでは用紙がA4のまま開き、ヘッダとフッタも刷られた（カードの実寸と改ページは効いた）。Playwrightの`page.pdf()`はChromiumでしか動かないので、自動の検証で分かるのはChromeの結果だけだ。用紙の大きさまで同じ結果にしたいなら、画面で用紙ぴったりのPDFを作る。ブラウザの印刷のままにするなら、用紙サイズ、余白、ヘッダとフッタを印刷の画面で確かめるよう、画面と手順書で案内する。判断基準は「この出力の見た目を決めているのは、こちらのコードか、利用者のブラウザの印刷設定か」。
- **ログインの要るローカルの画面を自動で撮るときは、`http://localhost`で開き、ログインの状態をファイルに保存して使い回す**。`Secure`の付いた`__Host-`のcookieは、`http://127.0.0.1`では保存されず、ログインの直後も未ログインの画面が出た。`http://localhost`では保存された。撮り直すたびにログインすると、ログインの回数の制限に当たって止まるので、最初の1回で`storageState`を保存し、以後はそれを読む。portlessのプロキシに届かないとき（curlが`SSL_ERROR_SYSCALL`を返す）は、開発サーバーのポートへ直接つなぐ（Playwright 1.63、2026-11に確認）。
- 読み込みに失敗した画像を同じURLで入れ直しても、ブラウザは文書の中に覚えた失敗を使い回し、取り直さない（Chromeで確認）。やり直しの導線では、URLを変える。
- **画面のラベルには、実装の語でなく、利用者が業務で使う語を書く。数値のラベルには、何と比べた値か、単位は何かを入れる**: 開発者の内部の語（「ヘッダー要約」「派生値」「抽出ステータス」）をそのまま出すと、利用者は意味を取れない。「差」「合計」だけのラベルは、何との差か、税込か税抜かが分からない。「今月ご請求サマリーとの差」「合計（税抜）」のように書く。判断基準: 「このラベルを見た現場の担当者が、隣の数字と何を比べているかすぐ分かるか？」
