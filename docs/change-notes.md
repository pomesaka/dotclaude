# 変更の知らせの書き方

> **TL;DR**: PR の本文、リリースノート、CHANGELOG のように「何が変わったか」を人に知らせる文は、その変更を知っておいてほしいステークホルダーごとに節を分け、1 つの変更を 1 行の「〜しました」で書く。普段の開発では、利用者・運営・開発の 3 つ。

PR の本文、リリースノート、CHANGELOG、更新のお知らせを書くときに読む。PR の本文の並びとテンプレートは create-pr のスキルにあり、この文書は、その中の文の決まりを持つ。

## 節を分ける

変更を、それを知っておいてほしいステークホルダーごとの節に分ける。読む人は、自分の節だけを読めば済む。ステークホルダーは「この変更で、見るもの、すること、頼るものが変わる人」だ。節の名前は、その人の呼び名にする。

普段の開発では、次の 3 つになる（pomesaka の指示、2026-11-18）。

| 節 | 誰 | 書くこと |
|---|---|---|
| 利用者 | サービスの画面を使う人 | 画面と操作がどう変わるか、何ができるようになったか、何が直ったか |
| 運営 | サービスを運営する人（pomesaka）。管理画面、運用の手順、知らせ、費用、監視を見る | 運営の作業、見るもの、判断がどう変わるか |
| 開発 | このコードを触る人。人の開発者も AI エージェントも | 仕組みが何をするようになったか（データ、処理、API、読む量）と、次に触るときの判断や手順の変化（頼る場所、もうしなくてよいこと、間違えたら止めてくれる型、テスト、文書） |

- ほかに影響を受ける人がいれば、その人の節を足す。API やデータの形を使う別のチーム、営業、顧客の担当者など。その人にしてほしいことがあれば、何を、いつまでにを書く
- 1 つの変更が何人に関係するなら、それぞれの節に、その人から見た言葉で書く。同じ文を写さない
- 利用者・運営・開発で変わらない節は、消さずに「変わりません」の 1 行を書く。読む人は、自分に関係が無いことを確かめられる。足した節は、変わるときだけ立てる
- 開発の節は、知っておかないと間違えることだけを書く。仕組みの入口、直す場所、守ること。関数名の一覧、主キーの並び、処理の細かい順番のように、diff とコードを読めば分かることは書かず、PR なら`<details>`に入れる。目安は 3〜5 行で、超えたら移せる行がないかを見る。WHY: 作業した本人は作りを全部知っているので、開発の節に作りの説明を全部書きがちで、読まれない長さに戻る
  - 書かない: 「送る日の決まりを core の純関数（digest-schedule.ts）に置きました。送る曜日（dueWeekdays）、前回の送信日（lastSentAt）、締めの時刻（cutoff）…」
  - 書く: 「まとめのメールを送る日と、何日分をまとめるかの決まりは、core の digest-schedule.ts にまとめました。送るタイミングを変えるときは、ここを直してください」
- 節の中は見出しで分けず、行を並べる。振る舞いとアウトカムは、同じ行に書く（「〜できるようになりました」は、振る舞いの変化と、それで何ができるかを 1 文で言う）
- 戻せない変更（migration、データの書き換え、送ったメール）と、デプロイの順番が要る変更は、節とは別に「影響範囲」として書く。見落とすと実害が出るため

## 1 行の書き方

任天堂の本体とソフトの更新データの知らせの書き方に倣う（公開されたルールは無く、実際の文から拾った。出典は下）。

- **1 つの変更を 1 行にする。** 文末は「〜しました」でそろえる
- **動詞を少なく保つ。** 「追加しました」「できるようになりました」「変更しました」「改善しました」「修正しました」「対応しました」でほとんど書ける。動詞で、新しいことか、直したことかが分かる
- **画面を使う人の節は、場所と条件を先に書く。** 「〈画面〉→〈項目〉で」「〈条件〉のとき」「〈何ができる・何が起きる〉」の順。テーブル名、関数名、ライブラリの名前は出さない
- **直したことは、症状を書く。** 「不具合を修正しました」でなく、「〈何〉が〈どうなる〉問題を修正しました」。何が直ったかが分からない知らせは、読む人の役に立たない
- **値を変えたら、前 → 後を書く。** 「上限を 10 → 20 件にしました」
- **並びは、新しくできること → 変わったこと → 直したこと。** 細かいものは、最後の 1 行にまとめてよい（「そのほか、いくつかの表示を直しました」）

例:

```
## 利用者
- 「設定」→「通知」で、まとめのメールを受け取る頻度（週 1 回・月 1 回・受け取らない）を選べるようになりました
- 一覧を幅の狭い画面で開いたとき、ページが横に動く問題を修正しました

## 運営
- 変わりません

## 開発
- 一覧の月ごとの件数を、明細の行でなく、月ごとの集計から読むようにしました（読む行 870 → 151）
- 件数の数え方を変えるときは、明細を数えず、集計を直してください。数の一致は統合テストが確かめています
```
