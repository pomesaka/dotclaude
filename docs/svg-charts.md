# SVG での自前チャート描画

ライブラリを使わず SVG の `<path>` の弧（arc）でチャートを自前描画するときに見落としやすい点。

## 100%（一周）のスライスは `<path>` の弧では描けない

`M cx,cy L start A r r 0 largeArc 1 end Z` 形式のパスは、円グラフの 1 スライスが
シェア 100% になったとき（他の値が全部 0、または行が 1 件しかない）start と end が
同じ座標になり、弧の始点と終点が一致してブラウザは何も描画しない（エラーにもならず
気づかないうちに消える）。

対処: シェアが 360° ちょうど（浮動小数演算なので `>= 359.99` 等で判定し、厳密な `=== 360`
にしない）のスライスだけ `<circle>` で描く分岐を用意する。

## 弧の `large-arc-flag` は「180° を超えるか」で決める

`A r r 0 <large-arc-flag> <sweep-flag> end`。スライスの中心角が 180° を超える
（`end - start > 180`）ときに `large-arc-flag` を 1 にしないと、SVG は同じ 2 点を結ぶ
もう一方の（短い）弧を描いてしまい、逆側の欠けた扇形になる。

## 凡例に載らない行の内訳は `<title>` 要素でネイティブツールチップにできる

行数が多い集計（例: 従業員が 100 人）で凡例を全件表示すると縦に伸びきる。
上位 N 件だけ凡例に出し、残りは各スライスの子要素に `<title>{ラベル}</title>` を
入れることでブラウザ標準のホバーツールチップとして読めるようにできる。
JS のイベントハンドラや外部ライブラリのツールチップ実装が不要。
ただしタッチデバイスではホバーが効かないため、凡例外の情報は事実上 PC 利用者限定になる
（モバイル比率が高い画面では上位 N を広げる・別途一覧を用意する等の代替が要る）。
キーボードだけの利用者も同じく到達できないので、畳んだ分は `<details>` 等で開ける
凡例として DOM に置く（ホバーのツールチップに代替させない）。

### `role="img"` を付けても Chrome は子孫をアクセシビリティツリーから落とさない

「図全体に `role="img"` + `aria-label` を付けたのだから、中のスライスの `<title>` は
読み上げに出てこない」は Chrome では成り立たない。`<title>` を持つ `<path>` は
`graphics-symbol`（`ignored: false`）としてツリーに残る（CDP の
`Accessibility.getFullAXTree` で実測・2026-09-11）。

WHY コメントに「role=img だから中身は隠れる」と書くと、読者はそれを検証済みの前提として
再利用する。実際の AT の読み上げ挙動まで検証できないなら、断言できる制約だけを書く
（上記なら「ポインタを重ねたときしか出ない」）。
